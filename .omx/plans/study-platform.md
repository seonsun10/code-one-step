## 1. 요구사항 요약

프로그래밍 언어와 프레임워크를 고르고, 설명을 학습하고, 여러 방식으로 문제를 풀고, 다음에 다시 접속했을 때 진도를 이어가는 한국어 우선 학습 사이트를 만든다. 객관식·주관식·오류 코드 식별·코드 수정 및 코딩테스트 경험을 제공한다. 초기 핵심 기능은 로그인 없이 모두에게 무료로 열고, 서버·데이터베이스·외부 유료 API·결제 비용을 쓰지 않는다. 학습 기록은 브라우저 안에 저장하고 백업/복원한다. 멤버십과 더 많은 콘텐츠는 사용자가 모이고 운영 필요가 확인된 이후 별도 단계로 판단한다.

### 실행 제약

- 현재 저장소는 새 프로젝트다. 구현 전에 기존 앱이나 데이터를 마이그레이션할 필요가 없다.
- 계획 문서 작성 단계에서는 앱 스캐폴딩·배포·서비스 가입·비용 지출을 실행하지 않았다. 현재는 이 기준선을 따라 G1부터 로컬 구현과 검증을 진행한다.
- 초기 구조는 외부 패키지 설치를 요구하지 않는 HTML, CSS, 브라우저 ES 모듈 정적 앱으로 정했다. npm 레지스트리 응답이 없어 초기 설치를 취소했으며, 이 방식은 앱을 빌드 없이 정적 배포할 수 있고 운영 의존성이 없다.
- Vercel CLI는 현재 설치되어 있지 않다. Vercel을 배포처로 선택하면 `npm i -g vercel` 설치를 권장하고 해당 CLI의 환경 변수·배포·로그 기능을 활용한다.

## 2. 제품 범위

### 첫 공개 버전에 포함

1. 공개 카탈로그와 한국어 학습 경로
2. 언어·프레임워크 트랙 예시: JavaScript, Python, Java, Spring Boot, React
3. 개념 설명, 코드 예제, 목표, 힌트, 정답과 풀이
4. 객관식, 짧은 주관식, 오류 코드에서 위치/원인 찾기, 코드 수정·리팩터링 문제
5. JavaScript 코딩 문제의 브라우저 내 실행과 테스트 채점
6. 현재 브라우저에서 진도·오답·학습 중 초안을 보존하고 다시 열기
7. 사용자 기록 JSON 내보내기와 가져오기
8. 반응형 디자인, 키보드 조작, 기본 접근성, 오류/저장 상태 안내

### 첫 공개 버전에서 제외

- 계정, 서버 DB, 기기 간 자동 동기화
- 서버에서 Java/Python 등 임의 코드를 실행하는 기능
- 로그인, 결제, 유료 멤버십, 유료 문제 잠금
- 생성형 AI 튜터, 외부 LLM API, 사용자 추적 분석
- 광고, 순위표, 소셜 피드, 실시간 협업, 모바일 앱
- 폭넓은 콘텐츠를 먼저 채우기 위한 검증 없는 문항 복제

### 학습 기록의 범위

초기에는 같은 브라우저 프로필에서 이어서 학습한다. 다른 브라우저나 기기로 자동 동기화되지 않는다. 브라우저 저장 데이터 삭제로 기록이 사라질 수 있으므로 JSON 백업/복원을 함께 제공하고 이 한계를 UI에 설명한다. 계정 동기화는 사용자 수요와 비용·개인정보 결정을 통과한 별도 목표로 둔다.

## 3. 성공 기준

- 새 방문자가 가입이나 결제 없이 언어/트랙 선택부터 첫 문제 풀이까지 도달한다.
- 지원하는 네 가지 초기 유형(객관식, 짧은 주관식, 오류 찾기, 코드 수정)에서 답 제출, 피드백, 풀이 확인, 다음 학습으로 이동할 수 있다.
- JavaScript 코딩 문제는 정상 종료·실패·시간 초과를 구분해 표시하며 브라우저 UI가 멈추지 않는다.
- 같은 브라우저에서 페이지를 새로 열면 학습 중 위치와 완료/오답 기록이 복원된다.
- 내보낸 학습 파일을 가져오면 사용자가 검토한 뒤 진도를 복원할 수 있고, 잘못된 파일은 현재 데이터를 손상시키지 않고 거부한다.
- 핵심 흐름을 키보드로 사용할 수 있고 좁은 화면에서 콘텐츠나 조작이 잘리지 않는다.
- 첫 공개 전에 콘텐츠 정답과 해설의 검토 상태, 빌드/정적 검사 결과, 배포처 비용 확인을 기록한다.
- 첫 공개 버전에 서버·DB·유료 API·결제 수단 비용이 없음을 의존성 및 배포 설정에서 검토한다.

## 4. 단계별 실행 계획

### G1 — 무료 정적 앱 기반과 공통 레이아웃 (10%)

작업: HTML, CSS, ES 모듈만 사용하는 정적 구조를 만든다. 런타임·개발 패키지 의존성이 없음을 확인하고, Node 내장 모듈로 로컬 정적 서버와 배포용 파일 복사를 제공한다. 공통 헤더/탐색, 홈, 트랙/학습 화면, 작은 화면 레이아웃, 디자인 토큰을 만든다.

완료 조건:

- Node.js가 있는 신규 환경에서 문서에 기재된 명령으로 로컬 실행과 정적 파일 복사가 된다.
- 홈에서 카탈로그와 샘플 학습 경로로 이동 가능하다.
- 휴대전화 폭과 데스크톱 폭에서 탐색 메뉴, 페이지 제목, 주요 동작이 겹치거나 잘리지 않는다.
- `docs/plan/decisions-and-help.md`에 외부 패키지를 설치하지 않는 구조와 무료 정적 배포 후보의 근거가 있다.

### G2 — 트랙 탐색 및 학습 콘텐츠 모델 (10%)

작업: 트랙 → 주제 → 학습 단위의 콘텐츠 스키마와 카탈로그를 만들고 샘플 콘텐츠를 연결한다. JavaScript/Python/Java 기초와 Spring Boot/React 소개는 각기 적합한 문제·설명으로 시작한다. 버전/출처/검수 상태 메타데이터를 포함한다.

완료 조건:

- 각 트랙은 난이도, 선수 지식, 목표가 보이고 해당 주제와 학습 단위로 탐색된다.
- 서로 다른 주제의 학습 단위 1개 이상이 콘텐츠 데이터로부터 렌더링된다.
- 화면 컴포넌트를 수정하지 않고 새 문항 데이터를 추가할 수 있다.
- 예제 콘텐츠의 정답·해설·버전 맥락 검수가 기록되어 있다.

### G3 — 개념 설명 및 학습 단위 화면 (10%)

작업: 학습 목표, 설명, 코드 예제, 예상 시간, 난이도, 힌트, 풀이, 이전/다음 이동 및 완료 상태를 구현한다. 완료·다시 보기 행동이 일관되고 저장 기능 추가 전 임시 상태가 혼란스럽지 않게 한다.

완료 조건:

- 학습 단위마다 목표·설명·예제·예상 시간·다음 행동이 표시된다.
- 힌트와 해설을 단계적으로 열 수 있고 모바일과 키보드에서 조작된다.
- 데이터 누락·잘못된 콘텐츠는 화면 전체를 중단시키지 않고 진단 가능한 오류 상태를 보인다.

### G4 — 객관식·주관식·오류 찾기 문제 (20%)

작업: 문제 렌더링/채점 계약과 답변 흐름을 구현한다. 정답과 오답에 이유를 제공하고, 빈 응답·재시도·해설 후 다음 이동을 처리한다. 짧은 주관식은 정규화 가능한 범위에만 자동 채점을 적용하고 애매한 답에는 기대 개념과 예시 답을 보여 준다. 잘못된 코드의 줄 선택 또는 범위 선택 UI를 제공한다.

완료 조건:

- 객관식, 짧은 주관식, 오류 위치 찾기 각각에서 입력·제출·결과·해설 흐름이 동작한다.
- 정답/오답/무응답/재시도 상태가 색만으로 구분되지 않는다.
- 객관식 선택지 순서가 매번 고정된 정답 위치에 의존하지 않도록 검증된다.
- 최소 1개 문항씩 기준 답변과 오답 설명이 검수되어 있다.

### G5 — 브라우저 JavaScript 코딩 문제 (15%)

작업: 코드 편집/작성, 지문과 제약·예시 입출력, 힌트, 제출 테스트를 연결한다. Worker에 코드만 전달하고 테스트 실행 결과와 사용자 메시지를 분리한다. 실행 중·통과·실패·문법/런타임 오류·시간 초과 상태를 표시한다.

완료 조건:

- 예제 코드 문제를 수정/실행/채점할 수 있고, 정상/실패 사례를 구분한다.
- 무한 루프가 UI 주 스레드를 막지 않으며 제한 시간이 지나면 Worker가 종료된다.
- 입력값과 출력 길이가 제한되고 사용자 코드에 저장소·비밀 데이터가 노출되지 않는다.
- 브라우저 Worker 보안 한계를 사용자 문구에서 과장하지 않는다.
- Python/Java 실행이 필요해지더라도 서버 실행 승인이 전에는 범위를 확장하지 않는다.

### G6 — 로컬 기록·재개·백업/복원 (15%)

작업: 저장 경계를 정의하고 스키마 버전, 완료/오답 기록, 마지막 학습 위치, 코드 초안을 보존한다. 진행률/최근 학습 화면을 제공하고 내보내기 파일 형식과 가져오기 검증을 만든다. 저장 공간을 사용할 수 없는 상황과 재설정 흐름을 안내한다.

완료 조건:

- 새로고침과 브라우저 재시작 후 최근 학습 위치, 완료/오답 기록이 유지된다.
- IndexedDB의 앱별 버전/마이그레이션 규칙이 정의되어 있다.
- JSON 내보내기 후 초기화 또는 별도 테스트 프로필에서 가져오면 내역이 복원된다.
- 손상·과대 크기·알 수 없는 스키마 데이터 가져오기는 원본 기록을 보존하며 거부된다.
- 사용자 화면에서 로컬 저장 범위와 기기 간 자동 동기화 부재를 알 수 있다.

### G7 — 접근성·품질·보안 검증 (10%)

작업: 콘텐츠/문항/저장/실행기의 실패 경로를 점검하고 자동 검사 및 수동 브라우저 검증을 수행한다. 키보드만으로 주요 과업을 끝내고, 좁은 화면 및 대비를 확인한다. 오류/빈 상태와 도움말을 정리한다.

완료 조건:

- 저장소가 제공하는 lint/typecheck/build 또는 동등한 검사가 통과한다. 미실행 검사는 사유가 명시된다.
- 핵심 흐름의 자동화 또는 재현 가능한 수동 확인이 기록된다.
- 코드 실행기 시간 제한/예외/출력 제한/Worker 정리가 확인된다.
- 키보드만으로 학습 경로 선택, 답 제출, 힌트, 다음 문제, 백업/복구가 가능하다.
- 모바일 핵심 화면, 대비, 포커스, 오류/빈 상태가 검토된다.

### G8 — 무료 공개 후보 및 사용자 피드백 준비 (10%)

작업: 비용이 없는 공개 경로를 구성한다. 선택한 호스팅의 현시점 무료 한도·약관·사용량 알림 가능성을 확인하고, 과금 옵션을 피한다. 피드백은 이메일 수집 대신 우선 재현 가능한 로컬/저장소 이슈 기록 등 무료 방식을 선택한다. 출시 체크리스트와 다음 콘텐츠 후보를 마련한다.

완료 조건:

- 배포 파이프라인과 공개 URL이 예상 비용 없이 작동하거나 비용이 발생하는 구간이 분명하게 설명된다.
- 배포 설정에 API 비밀값이나 불필요한 사용자 추적이 없다.
- 사용자가 콘텐츠 오류와 접근성 문제를 신고할 경로가 문서화되어 있다.
- 공개 전 확인 목록, 알려진 제약, 다음 단계 후보가 완료되어 있다.

### G9 — 단계별 교육과정 확장, 버전 검수, 디자인 정리 (기존 100% 가중치 밖의 추가 범위)

작업: 요청된 다섯 트랙 각각을 3개 순서형 단계로 나누고 각 단원의 선수 관계와 실제 진도를 연결한다. 객관식·주관식·오류 줄 찾기·코드 수정·JavaScript 코딩 문제를 추가한다. 검토 시점의 공식 언어/프레임워크 버전과 호환 범위를 출처에 연결한다. 차분한 한국어 UI, 밝게/어둡게/기기 설정, 좁은 화면과 상태 대비를 갖춘다. 새 계정/DB/외부 실행/결제/추적 서비스는 포함하지 않는다.

완료 조건:

- JavaScript, Python, Java, Spring Boot, React 각 트랙에 3개의 번호 단계와 정렬된 선수 단원 관계가 있고, 새 트랙 학습은 단계 개요부터 시작한다.
- 각 단원에 유효한 목표·설명·예제·문제·힌트·해설·해당 트랙의 검토 날짜/버전이 있고, 정답과 오답이 자동 카탈로그 검사에서 구분된다.
- 버전/호환성 주장은 확인 날짜와 공식 문서 링크가 있으며 draft/LTS/비-LTS 경계를 밝힌다.
- 모든 트랙이 홈과 트랙 목록/탐색에서 접근 가능하고, 좁은 화면과 밝게/어둡게 양쪽에서 핵심 풀이 흐름이 읽힌다.
- 자동 검사와 정적 빌드가 통과하고 패키지 의존성, 유료 서비스, 원격 DB/API, 사용자 계정, 결제는 추가되지 않는다.

## 5. Ultragoal 실행 순서와 체크포인트

1. 이 문서와 `docs/rules/`를 계획의 기준으로 읽는다. 계획 구현 전반을 단일 대규모 작업으로 처리하지 않는다.
2. G1부터 G8까지 순서대로 각 단계를 독립 검토 가능한 목표로 실행하고, 승인된 추가 범위는 G9로 따로 추적한다. 콘텐츠 모델은 G2/G9에서, 렌더링/채점은 G3/G4/G9에서 각각 검증한다.
3. 각 목표 시작 전 `docs/plan/progress.md`의 상태를 `진행`으로 바꾸고 목표 범위/완료 조건을 기록한다.
4. 각 목표가 완료되면 변경 파일, 검증 결과, 비용/서비스 경계 변경, 남은 이슈를 기록하고 완료율을 갱신한다.
5. 승인되지 않은 외부 비용·서비스·클라우드 데이터 전송이 필요해지는 경우 해당 기능을 보류하고 결정을 `docs/plan/decisions-and-help.md`에 남긴다. 나머지 비용 없는 작업은 계속한다.
6. 목표 간 요구가 충돌하면 임시 구현으로 덮지 말고 결정 ID를 기록한다. 기본 결정으로 계속 가능한 일은 계속 진행한다.
7. 실행 전 모델 설정에서 `gpt-6-luna`와 `xhigh`가 가능한지 확인한다. 지원되지 않으면 구현 목표 시작 전에 사용 가능한 조합을 결정으로 기록한다.

## 6. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 브라우저 저장은 기기 간 동기화가 안 되고 브라우저 데이터 삭제 시 사라질 수 있음 | 재방문·기기 변경 시 진도 손실 | 자동 계정 저장을 약속하지 않고 명확히 안내하며 JSON 백업/복원을 제공한다. |
| 브라우저 코드는 신뢰할 수 없음 | 메인 스레드 멈춤, 과도한 자원 사용, 브라우저 보안 기대 위반 | Worker, 강제 종료 시간, 출력/입력 제한 및 테스트를 제공한다. Worker만으로 완전한 보안을 보장한다고 말하지 않는다. |
| 다양한 언어 자동 실행은 무료만으로 운영하기 어려움 | 서버 비용 및 악용 위험 | 첫 자동 실행은 JavaScript 범위로 한정한다. 다른 언어는 학습 콘텐츠로 먼저 제공한다. |
| 프레임워크 버전 변화로 설명과 문제 정답이 낡을 수 있음 | 잘못된 지식 학습 | 버전/출처를 남기고 공개 콘텐츠를 주기적으로 재검토할 수 있게 한다. |
| 무료 호스팅 조건은 바뀌거나 한도를 넘을 수 있음 | 서비스 중단 또는 비용 발생 | 배포 시 공식 약관을 다시 확인하고 예상치 못한 과금 기능은 끈다. |
| 많은 주제를 한 번에 다뤄 콘텐츠가 얕아질 수 있음 | 학습 효과 감소 | 트랙 수보다 검수 완료된 학습 단위 수와 풀어본 사람 피드백을 우선한다. |
| 구독을 너무 일찍 도입하면 신뢰와 접근성을 해칠 수 있음 | 사용자 획득과 유지 저하 | 초기에 전체 핵심 흐름 무료 유지, 수요와 유지 비용 확인 후 별도 승인 단계로 둔다. |

## 7. 검증 및 릴리스 기준

- 각 단계의 구현 검증은 `docs/rules/coding.md`의 검증 기준을 따른다.
- 콘텐츠 릴리스는 `docs/rules/content.md`에 따른 정답/해설 검토를 완료해야 한다.
- 개인정보와 코드 실행 검토는 `docs/rules/privacy-security.md`를 따른다.
- UI 검토는 `docs/rules/design.md`의 모바일·키보드·대비 규칙을 따른다.
- 무료 운영 주장은 배포 시점의 공식 요금/약관 근거가 있을 때만 한다.
- 공개 전에 알려진 제약과 해결되지 않은 사용자 도움 요청을 `docs/plan/decisions-and-help.md`에서 확인한다.

## 8. 계획 완료/범위 외 결정

계획과 규칙 문서 작성은 완료되었고 구현 실행이 시작되었다. 다음 사항은 실행 중 아래처럼 처리한다.

- 이 개발 환경에서 요청 모델·추론 조합이 선택 가능한가? Codex 목표 추적을 생성했으며, 실제 추론 수준은 이 인터페이스에서 바꾸거나 확인할 수 없어 요청 설정 적용 여부는 미확인으로 기록한다.
- 학습 진도를 같은 기기에서 저장·복원하는 초기 범위가 충분한가?
- 정식 사이트 이름이 정해져 있는가? 정해지지 않았다면 `Study Web`을 작업명으로 사용한다.
- 초기 콘텐츠 제작량과 우선순위는 사용 피드백에 맞춰 단계별로 조정한다.

사이트 이름과 콘텐츠 순서는 현재 계획을 멈추게 하는 블로커가 아니다. 계정 동기화나 다중 언어 서버 코드 실행은 비용과 개인정보 결정이 필요하므로 승인 전 구현하지 않는다.
