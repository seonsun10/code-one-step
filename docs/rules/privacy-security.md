# 개인정보 및 보안 규칙

## 데이터 최소화

- 초기 버전은 계정, 이메일, 실명, 비밀번호, 서버 분석 이벤트를 요구하지 않는다.
- 사용자 진도와 답안은 기본적으로 사용자 브라우저에만 저장한다.
- 내보내기 파일에 개인 식별 정보나 불필요한 브라우저 데이터가 들어가지 않도록 한다. 가져오기 전에 데이터 크기와 구조를 검증하고 미리보기 또는 명확한 확인 상태를 제공한다.
- 브라우저 데이터가 삭제되거나 기기를 바꾸면 자동 동기화되지 않는다. 안내와 백업/복구 기능으로 기대치를 분명히 한다.

## 임의 코드 및 콘텐츠 입력

- 사용자가 입력한 코드와 가져온 콘텐츠를 신뢰하지 않는다.
- 임의 코드는 메인 UI 스레드에서 실행하지 않는다. 별도 Worker에서 실행하되, 이를 완전한 보안 경계라고 설명하지 않는다.
- 코드 실행에 인증 정보, 비공개 정답 데이터 외의 서버 데이터, 로컬 파일 접근, 부모 창의 참조를 넘기지 않는다.
- Worker 종료, 시간 제한, 출력 제한, 오류 처리와 메모리 증가 대응을 검증한다.
- HTML 삽입이나 위험한 문자열 실행으로 가져온 Markdown·텍스트를 렌더하지 않는다. 필요하면 안전한 렌더링 정책을 적용한다.
- 강한 격리 실행이 필요한 언어와 채점은 서버 실행 환경의 격리 방식, 악용 방지, 비용, 로그·보관 정책을 승인받기 전까지 제공하지 않는다.

### PostgreSQL 코드 실행

- SQL 제출 내용은 외부 서버에 전송하지 않고 로컬 PGlite Web Worker에서만 실행한다. 매 실행마다 새 메모리 DB를 만들고 종료 때 폐기한다.
- 채점은 단일 `SELECT`/CTE만 허용하며 읽기 전용 트랜잭션으로 감싼다. 입력 20 KiB, 사례 12개, 반환 100행·40열·100 KiB, 제한 시간 15초를 넘으면 중단한다.
- 문제의 예시·기대값은 정적 사이트에 포함되므로 공개 자료로 취급한다. 비밀 테스트 또는 안전한 격리 실행을 제공한다고 설명하지 않는다.
- Worker는 브라우저 자원 고갈이나 엔진 취약점을 완전히 막지 못한다. 행·열·출력·시간 제한과 disposable DB는 위험을 줄이는 방어층이며, 강한 공격자 격리가 필요한 사용 사례에는 이 로컬 실행기를 사용하지 않는다.

## 편집기 패키지와 브라우저 정책

- CodeMirror는 공식 npm 레지스트리에서 잠금 파일에 기록된 패키지로만 설치한다. 배포물에는 편집기 번들과 오픈소스 라이선스 고지를 포함하며 실행 중 외부 CDN이나 패키지 서버에 요청하지 않는다.
- `npm audit`는 공개된 보안 권고와 대조하는 점검이지 바이러스 검사나 악성 패키지 부재를 보증하는 수단은 아니다. 설치 출처·잠금 파일 무결성·라이선스·감사 결과를 함께 확인하고, 결과를 “바이러스가 절대 없다”고 과장하지 않는다.
- CodeMirror가 화면 스타일 시트를 주입하므로 앱의 `style-src`는 `'self' 'unsafe-inline'`만 허용한다. 외부 스타일·스크립트·연결 출처는 허용하지 않는다. 코드 실행 iframe의 `default-src 'none'`, 네트워크 차단 및 별도 실행 정책은 유지한다.
- 편집기에서 작성한 코드는 기존처럼 사용자 브라우저 안에 저장한다. 편집기 라이브러리는 학습자의 코드나 진도 데이터를 수집하거나 전송하지 않는다.

## 서비스 도입 전 필수 기록

외부 데이터 전송 또는 비용이 발생할 수 있는 서비스를 추가하기 전 다음을 기록한다: 목적, 전송 데이터, 보관 위치/기간, 계정 및 삭제 방식, 무료 한도와 초과 비용, 보안 책임, 대체 방법, 승인된 구현 범위.
