# 학습 콘텐츠 규칙

## 콘텐츠 구성

각 학습 트랙은 `언어/프레임워크 → 주제 → 학습 단위 → 문항`으로 탐색할 수 있어야 한다. 학습 단위에는 목표, 선수 지식, 난이도, 예상 시간, 설명, 예시, 연습, 해설, 관련 단위를 포함한다.

- 각 트랙의 학습 순서는 번호가 있는 3개 이상의 단계로 나누고, 단원 번호와 선수 단원 관계를 기록한다. 학습자는 순서를 이해할 수 있어야 하며, 점수로 다음 단원을 잠그지 않는다.
- 신규 트랙은 값/기초 문법에서 조건·반복, 함수·자료구조, 객체/프레임워크 흐름처럼 선수 개념부터 쌓는다. 프레임워크 단원은 필요한 언어 개념을 명시한다.
- 화면에 보이는 진도·단원 수·이어하기 위치는 실제 카탈로그와 로컬 기록에서 계산한다. 새 트랙은 첫 문제로 바로 보내기 전에 단계 개요를 보여 준다.

## 문항 유형

- 객관식: 질문·선택지·정답·오답별 설명을 제공한다. 보기의 위치만 외워 정답을 맞히지 못하게 정답 순서를 조정한다.
- 주관식: 기대 개념과 허용 가능한 답의 기준을 제공한다. 초기 자동 평가는 단순·명확한 정규화 규칙에 한정하고, 모호한 답은 기준 답과 비교해 스스로 확인할 수 있게 한다.
- 오류 찾기: 오류가 있는 줄 또는 코드 범위, 잘못된 이유, 수정안을 함께 설명한다.
- 코드 수정·리팩터링: 시작 코드, 요구사항, 제약, 예시 입출력, 테스트 기준, 힌트 단계를 명시한다.
- 개념 카드·짧은 복습: 한 번에 하나의 목표를 다루고, 정답 확인 뒤 설명을 제시한다.

## 품질 기준

- 모든 문항에는 하나의 학습 목표와 검토된 정답 기준이 있어야 한다.
- 풀이는 정답을 반복하는 데 그치지 않고 근거를 설명한다.
- 코드 예제는 별도 명시가 없으면 완결된 최소 예제이며 언어와 버전 맥락을 적는다.
- 프레임워크 문제는 어떤 버전 또는 일반 원칙에 관한 것인지 표시한다. 공식 문서를 참조한 날짜나 링크가 필요한 주제는 출처를 기록한다.
- 버전 기록은 해당 날짜의 공식 안정판/LTS와 호환 범위를 검증해 적는다. draft, preview, 비-LTS, 미지원 버전은 안정 기능과 혼합하지 말고 화면에서 그 상태를 밝힌다. 동적으로 바뀌는 버전 주장은 출처와 재검토 날짜를 함께 둔다.
- 모든 선택지는 학습 목표와 일관되어야 하며 정답뿐 아니라 오답 판단의 이유도 설명한다. 오류 찾기 정답 줄은 실제 코드 결함과 해설의 수정안을 가리켜야 한다.
- 실행 환경이 없는 언어의 코드 수정 자동 채점은 문항별 전체 함수·메서드 구조 패턴으로 제한하고, 패턴이 없으면 정답 처리하지 않는다. 부분 문자열 포함 여부만으로 정답 처리하지 않는다. 구조 패턴 검사는 코드를 실행하거나 동작을 검증한 것처럼 표현하지 말고, 허용하는 형식과 범위를 화면에 설명한다. 실행/호환성 검증이 없는 프레임워크 예시는 개념 스니펫임을 분명히 한다.
- 오답 설명과 힌트는 답을 너무 일찍 노출하지 않으면서도 막힌 사용자가 다음 시도를 할 수 있도록 한다.
- 미검증 콘텐츠는 공개 완료로 표시하지 않는다. 콘텐츠 리뷰 여부를 진척 관리에 남긴다.

## 표현

- 용어를 처음 쓸 때 짧게 풀어 설명하고, 언어별 표기 관례를 따른다.
- 초보자를 탓하는 표현을 쓰지 않는다. 오답은 다음 시도를 돕는 중립적인 피드백으로 표현한다.
- 출처가 있는 내용을 그대로 복제하지 말고 자체 설명과 예제로 가르친다. 라이선스를 확인할 수 없는 문제 세트를 가져오지 않는다.
