# 디자인 규칙

## 기본 방향

- 한국어 초보 학습자를 우선하는 차분하고 읽기 쉬운 학습 UI를 만든다.
- 장식보다 개념 이해, 코드 가독성, 문제 풀이 상태의 명료성을 우선한다.
- 과한 그라데이션, 부유 장식, 반복 카드, 의미 없는 영문 소문자 라벨 등 템플릿형 대시보드 장식은 피한다. 사용자를 돕는 정보 구조와 여백, 뚜렷한 제목으로 시각적 위계를 만든다.
- 화면의 본문과 도움 문구는 14px 이상을 기본으로 하고, 한국어 문장을 지나치게 작고 옅게 표시하지 않는다.
- 화면마다 하나의 주요 다음 행동을 분명하게 표시한다.
- 에러, 힌트, 정답, 완료, 저장 중 상태를 일관된 문구와 시각 표현으로 알린다.

## 레이아웃과 반응형

- 모바일 폭에서도 본문·보기·풀이 버튼·코드 예제가 잘리지 않고 조작 가능해야 한다.
- 긴 학습 화면은 읽는 영역의 폭을 제한해 문장과 코드가 과도하게 길어지지 않게 한다.
- 작은 화면에서 내비게이션과 학습 콘텐츠의 우선순위를 유지하고, 가로 스크롤에 의존하는 문항 UI를 만들지 않는다.
- 코드 블록은 가로 스크롤이 가능해야 하며, 페이지 전체 가로 스크롤을 만들지 않는다.
- 홈과 경로 목록에서 다섯 개 현재 트랙을 모두 찾을 수 있고, 새 트랙은 번호가 있는 학습 단계 개요부터 시작할 수 있다.

## 접근성

- 본문 텍스트와 인터랙션은 WCAG AA 대비 목표를 적용한다.
- 키보드만으로 트랙 선택, 응답 제출, 힌트 표시, 다음 문제 이동을 할 수 있어야 한다.
- 포커스 표시를 숨기지 않고, 포커스 순서는 시각적 순서와 일치시킨다.
- 상태와 정오답을 색만으로 전달하지 않으며, 입력 요소와 버튼에 읽을 수 있는 이름을 제공한다.
- 동작·애니메이션을 줄이기 설정을 존중하고, 시간 제한 실행은 남은 시간과 종료 이유를 텍스트로 알려 준다.
- 밝게/어둡게/기기 설정 선택을 제공하고, 명시 선택을 같은 브라우저에 저장한다. 두 색상 테마의 본문, 보조 텍스트, 폼, 오답/정답 상태를 각각 대비 확인한다.

## 디자인 시스템

- 색, 간격, 타이포그래피, 경계선, 모서리, 포커스 표현을 토큰으로 관리한다.
- 공통 버튼, 입력, 선택지, 알림, 코드 블록, 진행 표시를 재사용한다.
- 제품 화면에서 기술 구현 설명을 노출하지 않는다. 사용자에게 필요한 선택과 결과를 설명한다.
- 디자인 규칙을 바꿀 때에는 관련 화면과 접근성 영향을 함께 검토한다.
