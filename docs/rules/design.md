# 디자인 규칙

## 기본 방향

- 한국어 초보 학습자를 우선하는 차분하고 읽기 쉬운 학습 UI를 만든다.
- 화면 문구는 부담 없는 자연스러운 한국어로 쓴다. 번역투 명사보다 익숙한 말과 짧은 동사를 쓰고, 사용자를 재촉하는 명령형을 피한다.
- 장식보다 개념 이해, 코드 가독성, 문제 풀이 상태의 명료성을 우선한다.
- 과한 그라데이션, 부유 장식, 카드형 콘텐츠 상자, 의미 없는 영문 소문자 라벨 등 템플릿형 대시보드 장식은 사용하지 않는다. 콘텐츠를 카드형 상자로 감싸지 않는다. 콘텐츠는 제목·여백·얇은 구분선으로 나누고, 목록은 행으로 표현한다.
- 화면의 본문과 도움 문구는 14px 이상을 기본으로 하고, 한국어 문장을 지나치게 작고 옅게 표시하지 않는다.
- 한글은 기기에 설치된 가독성 높은 산세리프 글꼴을 우선 사용하고, 제목의 과한 굵기와 자간 압축을 피한다. 본문은 편안한 행간을 유지한다.
- 주요 버튼·선택지·입력창은 조작 요소임이 드러나도록 모서리를 둥글게 한다. 학습 설명과 문제 본문을 둘러싸는 테두리·배경·둥근 모서리 컨테이너는 만들지 않는다.
- 코드 예제와 코드 편집기는 언어 문법에 맞는 색으로 선언, 이름, 함수, 문자열, 숫자, 주석 등을 구분하고 줄 번호를 제공한다. 드래그 선택 글자는 배경과 명확히 구분한다.
- 코드 편집기는 라이트·다크 테마 각각 전용 전경색·배경색·선택색·포커스 색을 사용하고, 일반 본문과 구분되는 충분한 대비를 확보한다. 입력 글자 위에 색상 표시층을 겹칠 때 글꼴·크기·행간·자간·탭 폭·스크롤 위치를 입력창과 맞춘다.
- 화면마다 하나의 주요 다음 행동을 분명하게 표시한다.
- 검수 여부나 제작 진척 같은 내부 작업 상태는 사용자 화면에 표시하지 않는다. 이용 가능 여부를 알려야 할 때는 현재 상태와 다음 행동만 짧게 안내한다.
- 사용자의 선택·다음 행동·풀이 결과·기록 보호에 필요하지 않은 문장은 노출하지 않는다. 가까운 영역에 이미 보이는 총량·진도는 반복하지 않고, 제품 화면에 구현·검수 과정 설명을 보여주지 않는다.
- 각 언어와 프레임워크는 알아볼 수 있는 고유 상징 이미지로 표시한다. 두 글자 약칭을 로고처럼 임의로 만들지 않는다. 전체 기술 이름도 아이콘 옆에 텍스트로 표시하고, 아이콘은 색에만 의존하지 않도록 형태가 분명해야 한다. 외부 이미지 호출 없이 로컬 SVG로 제공한다.
- 에러, 힌트, 정답, 완료, 저장 중 상태를 일관된 문구와 시각 표현으로 알린다.
- 문제 화면은 질문, 코드, 답변 선택/입력, 채점 결과, 풀이 설명을 제목·읽기 순서·간격·얇은 구분선으로 구분한다. 영역마다 별도 색 면이나 카드 테두리를 두지 않는다. 오늘의 문제 이동은 바깥 테두리와 칸 배경 없이 링크·상태·얇은 내부 구분선으로 표시한다. 코드가 질문 문자열에 포함되어도 읽을 수 있는 코드 블록으로 렌더링한다.

## 레이아웃과 반응형

- 모바일 폭에서도 본문·보기·풀이 버튼·코드 예제가 잘리지 않고 조작 가능해야 한다.
- 긴 학습 화면은 읽는 영역의 폭을 제한해 문장과 코드가 과도하게 길어지지 않게 한다.
- 작은 화면에서 내비게이션과 학습 콘텐츠의 우선순위를 유지하고, 가로 스크롤에 의존하는 문항 UI를 만들지 않는다.
- 코드 블록은 가로 스크롤이 가능해야 하며, 페이지 전체 가로 스크롤을 만들지 않는다.
- 홈과 경로 목록에서 다섯 개 현재 트랙을 모두 찾을 수 있고, 새 트랙은 번호가 있는 학습 단계 개요부터 시작할 수 있다.

## 접근성

- 본문 텍스트와 인터랙션은 WCAG AA 대비 목표를 적용한다.
- 키보드만으로 트랙 선택, 응답 제출, 힌트 표시, 다음 문제 이동을 할 수 있어야 한다.
- 부가 참고 자료는 기본 접힘으로 제공할 수 있으며, 열고 닫는 항목은 키보드와 화면 낭독기에서 동작하는 기본 HTML disclosure를 사용한다. 제목과 본문에는 좌우 여백을 두고, 펼친 상태는 +/− 아이콘만 바꾸지 말고 제목 줄의 배경·강조선·글자색 등으로도 알아볼 수 있게 한다. 지원되는 브라우저에서는 열고 닫힐 때 내용이 부드럽게 움직이도록 하되, 동작 줄이기 설정을 존중하고 미지원 브라우저의 기본 동작도 유지한다. 화면 낭독기는 기본 disclosure 상태를 읽을 수 있어야 한다.
- 키보드 조작 요소의 포커스 표시를 숨기지 않고, 포커스 순서는 시각적 순서와 일치시킨다. 화면 전환 때 안내를 위해 잠시 포커스하는 제목은 조작 요소가 아니므로 네모 포커스 테두리를 표시하지 않는다.
- 상태와 정오답을 색만으로 전달하지 않으며, 입력 요소와 버튼에 읽을 수 있는 이름을 제공한다.
- 동작·애니메이션을 줄이기 설정을 존중하고, 시간 제한 실행은 남은 시간과 종료 이유를 텍스트로 알려 준다.
- 첫 화면은 기기 색상 설정을 따른다. 상단 해/달 아이콘 버튼으로 밝은 모드와 어두운 모드를 전환하고 명시 선택을 같은 브라우저에 저장한다. 두 색상 테마의 본문, 코드, 답변 영역, 보조 텍스트, 폼, 오답/정답 상태를 각각 대비 확인한다.

## 디자인 시스템

- 색, 간격, 타이포그래피, 경계선, 모서리, 포커스 표현을 토큰으로 관리한다.
- 공통 버튼, 입력, 선택지, 알림, 코드 블록, 진행 표시를 재사용한다.
- 제품 화면에서 기술 구현 설명을 노출하지 않는다. 사용자에게 필요한 선택과 결과를 설명한다.
- 디자인 규칙을 바꿀 때에는 관련 화면과 접근성 영향을 함께 검토한다.
