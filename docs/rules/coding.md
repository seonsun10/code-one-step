# 코드 작성 및 검증 규칙

## 구현 규칙

- TypeScript를 기본 후보로 삼는다. 프로젝트가 외부 빌드 도구 없이 브라우저 기본 모듈만 사용하는 편이 더 단순할 때는 JavaScript와 JSDoc 타입 주석(`// @ts-check`)을 사용한다. 명시적 이유가 없으면 타입 회피용 `any`와 중복 추상화를 추가하지 않는다.
- 작은 변경을 만들고 관련 경계를 명확히 한다: 콘텐츠, 문제 렌더링/채점, 브라우저 저장, 코드 실행, 화면 UI.
- 사용자 입력과 가져온 JSON은 읽기 전에 형식과 크기를 검증한다.
- 화면 상태와 저장 상태를 구분한다. 저장 실패가 조용히 진도 유실로 이어지지 않도록 오류를 사용자에게 알리고 다시 시도 또는 데이터 내보내기 경로를 제공한다.
- 접근성 의미 요소와 키보드 조작을 보존한다. 시각적 상태만으로 정답·진도 정보를 전달하지 않는다.
- 라이브러리·프레임워크 API가 불확실하거나 달라질 수 있으면 구현 당시 공식 문서를 확인한다.

## 검증 규칙

- 동작을 바꾸는 작업에는 변경 범위에 맞는 자동 검증을 추가하거나 실행한다.
- 문제 유형에는 정상 정답, 오답, 빈 응답, 경계값, 저장 후 재개 흐름을 확인한다.
- 데이터 내보내기·가져오기는 손상·누락·다른 스키마 버전 입력을 다룬다.
- 코드 실행기는 정상 종료, 런타임 오류, 무한 루프 시간 초과, 출력 제한, Worker 재생성을 확인한다.
- 변경 후 저장소에 있는 관련 검사와 빌드를 실행한다. 실행하지 못한 항목과 이유를 별도로 표시한다.
- 정적 사이트 공개 전에는 `npm run check:release`로 clean build와 배포 산출물의 정적 파일·호스트 한도·비밀/개인 기록 제외, runtime 의존성, CSP 제거 규칙, 외부 연결 및 외부 스크립트 출처 제한을 확인한다. 이 로컬 검사는 공개 URL에서 하는 최종 확인을 대신하지 않는다.
- 수동 확인은 브라우저 크기, 키보드 이동, 좁은 화면을 포함하고 재현 절차를 기록한다.

## 작업 종료 시

수정 파일, 검증한 명령과 결과, 남은 위험 또는 차단 결정을 요약한다. 계획의 완료 체크와 수치는 증거가 확인된 경우에만 갱신한다.
