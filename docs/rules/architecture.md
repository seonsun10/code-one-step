# 기술 및 구조 규칙

## 초기 구조

- 첫 버전은 HTML, CSS, 브라우저 ES 모듈로 만든 정적 웹 앱이다. 프레임워크·런타임 의존성을 두지 않고 소스 자체를 정적 배포할 수 있게 한다.
- 로컬 개발 서버는 정적 파일만 제공한다. 앱 기능을 처리하는 서버 API나 데이터베이스를 만들지 않는다.
- 라이브러리나 프레임워크가 꼭 필요한 기능은 구체적인 이유, 배포 용량, 라이선스, 공급 경로, 업데이트 방법을 결정 기록에 남긴 뒤 검토한다. CodeMirror 6는 편집기 기능의 구체적 요구와 모바일 브라우저 지원을 위해 허용한 예외다. 해당 패키지는 개발 의존성에만 두고 공식 npm 레지스트리에서 잠금 파일과 함께 설치하며, 정적 배포물에 로컬로 묶고 라이선스 고지를 포함한다.
- 초기 버전은 클라이언트에서 동작하는 학습 경험으로 구성한다. 서버 API, 데이터베이스, 계정 서비스, 결제 서비스는 포함하지 않는다.
- 외부 서비스가 필요해지는 순간에는 관련 플랫폼 지침과 비용·개인정보 검토를 먼저 한다.
- 콘텐츠를 화면 컴포넌트에서 분리한다. 트랙, 주제, 학습 단위, 문항, 선택지, 테스트 사례, 힌트, 풀이 및 버전 정보를 저장소 안의 검토 가능한 텍스트 자료로 관리한다.
- 문항 렌더링은 문항 데이터와 유형별 표시·채점 동작을 연결한다. 각 문제 화면마다 중복된 정답 로직을 복사하지 않는다.

## 브라우저 저장

- 작은 설정값은 `localStorage`, 응답 이력·초안·진도처럼 항목이 늘 수 있는 데이터는 `IndexedDB`를 기본 후보로 삼는다.
- 저장 접근을 UI 컴포넌트 곳곳에 분산하지 않고 저장소 경계로 모은다.
- 저장 데이터에는 스키마 버전을 포함하고, 읽기 실패 및 이전 버전 변환을 처리한다.
- 같은 출처의 여러 탭이 동시에 저장할 때 Web Locks를 지원하는 브라우저에서는 저장 순서를 직렬화한다. 다른 탭이 먼저 저장한 오래된 화면의 기록은 덮어쓰지 않고 백업 또는 최신 기록 불러오기를 안내한다.
- 학습 내역을 JSON으로 내보내고 가져오는 기능을 제공해 브라우저 초기화나 기기 변경 시 복원할 수 있게 한다.
- 기본 동작은 현재 브라우저와 기기에 한정된다. 계정 동기화는 초기 범위가 아니며 별도의 비용·보안 결정을 필요로 한다.
- 현재 IndexedDB 데이터베이스/저장소 버전은 1이고 진행 데이터 형식 버전은 2다. 버전 1 기록은 버전 2 구조로 변환해 읽는다. IndexedDB 구조를 바꿀 때 `DATABASE_VERSION`을 올리고 `onupgradeneeded` 트랜잭션 안에서 기존 기록을 보존하는 마이그레이션을 추가한다. 진행 데이터 형식은 별도 변환 함수를 추가한 경우에만 버전을 올린다. 가져온 백업의 이전/미래 버전을 임의로 읽거나 덮어쓰지 말고, 알려진 변환이 없으면 원본 기록을 유지한 채 거부한다.

## 코드 실행기 경계

- 초기 자동 실행은 별도 Web Worker에서 실행 가능한 JavaScript 문제에만 제공한다.
- 실행별 시간 제한을 두고, 제한을 넘으면 Worker를 종료·재생성한다. 출력 크기와 입력 크기를 제한한다.
- 채점 테스트와 기대값은 사용자에게 보여 주는 문제 설명과 분리해 둔다.
- 결과 기반 코딩 문제는 함수 반환값을 테스트 사례의 기대값과 비교한다. `console.log` 표준 출력은 별도로 표시하며 반환값 채점과 혼동하지 않는다. 제공한 공개 사례만 통과했음을 알리고 모든 입력을 증명하는 것처럼 안내하지 않는다.
- 최신 실행 상태와 사례별 결과는 크기 제한을 적용한 선택 필드로 브라우저 풀이 기록에 저장해 새로고침 뒤 복원한다. 기존 풀이와 백업은 선택 필드가 없어도 읽을 수 있어야 한다.
- Web Worker는 악성 코드에 대한 완전한 보안 샌드박스가 아니다. 민감한 데이터·네트워크 권한·서버 비밀값을 전달하지 않는다. 브라우저 경계에서 확실히 제한할 수 없는 기능을 전제하지 않는다.
- Java, Python 등 서버 런타임이 필요한 언어의 임의 코드 채점은 서버 격리 실행 환경을 새로 설계하고 승인받기 전에는 만들지 않는다. 별도 비용이 전혀 들지 않는다고 가정하지 않는다.

### PostgreSQL 로컬 실습

- PostgreSQL 실습은 공식 npm 레지스트리의 `@electric-sql/pglite` 0.5.8을 빌드 시 정적 자산으로 묶어 브라우저 안에서 실행한다. 원격 DB·서버·계정은 사용하지 않는다.
- 학습 내용은 PostgreSQL 18.6 안정판을 기준으로 설명하지만, 현재 포함한 PGlite 0.5.8 엔진은 PostgreSQL 18.3 기반이다. 기능 호환을 확인하지 않은 PostgreSQL 18.6 변경 사항을 실행 가능한 기능처럼 가르치지 않는다. PostgreSQL 19 Beta 4는 미리보기로만 표기한다.
- 제출 쿼리는 한 개의 `SELECT` 또는 CTE로 제한하고, 읽기 전용 트랜잭션 안의 폐기 가능한 메모리 DB에서 실행한다. 사용자 코드와 학습 자료를 네트워크로 보내지 않는다.
- SQL 입력 20 KiB, 테스트 사례 12개, 결과 100행·40열·100 KiB, 실행 15초 제한을 유지한다. Worker 종료는 실행 취소와 자원 상한을 돕지만 악성 입력에 대한 완전한 보안 샌드박스는 아니다.
- PGlite WASM/데이터 파일과 Apache-2.0 고지를 정적 배포물에 포함한다. 빌드 산출물 용량과 호스트 한도를 출시 검사에서 확인하며, 런타임에 CDN이나 패키지 서버를 호출하지 않는다.

## 코드 입력 편집

- 코드 작성·수정 입력에는 CodeMirror 6을 사용한다. JavaScript/JSX/TypeScript, Python, Java의 언어 지원 모듈만 추가하고 실행기·자동 완성 서버 등 불필요한 기능은 포함하지 않는다.
- CodeMirror 패키지는 `devDependencies`에만 두고 `package-lock.json`으로 버전·무결성 해시를 고정한다. 빌드 때 편집기 코드를 정적 파일로 묶고 타사 라이선스 전문을 산출물에 넣는다. 브라우저에서는 CDN, 원격 스크립트, 패키지 레지스트리에 접속하지 않는다.
- 편집기 입력은 기존 브라우저 초안 저장 경계에 연결한다. 코드 길이 제한을 유지하고, 편집기 해제 때 인스턴스와 이벤트를 정리한다.

## 의존성·배포

- 기본 웹 플랫폼 기능과 기존 의존성을 우선한다. 명시적인 필요·유지 상태·라이선스 확인 없이 새 패키지를 추가하지 않는다.
- 새 패키지 설치는 공식 패키지 레지스트리의 잠금 파일 및 라이선스 확인, 취약점 감사로 검토한다. 감사 결과는 알려진 취약점 신호만 나타내며 악성코드 검사를 대신한다고 말하지 않는다.
- CodeMirror 편집 스타일 삽입을 위해 앱 문서에만 `style-src 'self' 'unsafe-inline'`을 허용한다. 외부 스타일 출처는 허용하지 않으며 스크립트 출처는 `'self'`, 앱 연결은 `'self'`로 유지한다. 코드 실행 iframe의 정책은 변경하지 않는다.
- 런타임에 호출되는 유료/외부 API에 의존하지 않는다.
- 호스팅 무료 플랜의 현재 제한과 약관은 배포 시점에 확인한다. 무료 플랜이 영구 무료라는 표현은 쓰지 않는다.
- 현재 Vercel CLI는 설치되어 있지 않다. Vercel 배포를 선택할 때는 `npm i -g vercel` 설치를 권장한다. 이 CLI를 쓰면 `vercel env pull`, `vercel deploy`, `vercel logs` 등의 명령을 사용할 수 있다. 초기 계획만으로 설치하거나 환경 변수를 가져오지는 않는다.
