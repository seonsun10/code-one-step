## 도달할 목표

학습자가 프로그래밍과 AI가 어떻게 동작하는지 이해하고, 스스로 코드를 작성·읽기·테스트·수정하며, AI가 만든 결과의 오류와 한계를 찾아 근거를 들어 검증·보완하도록 돕는다. 초보에서 시작해 실무 문제를 독립적으로 다루고 고급 개발에 필요한 판단을 연습하는 단계적 학습 경로를 만든다.

사이트 수료만으로 고급 개발자와 동등해진다고 약속하지 않는다. 대신 설명, 미지의 문제에 대한 전이, 테스트, 코드 리뷰, 설계 선택, 유지보수 과제에서 확인할 수 있는 역량을 목표로 삼는다.

## 고정 경계

- 핵심 학습은 무료로 제공하고 한국어 초보 학습자를 우선한다.
- AI 이론과 실습은 사이트 내부에서 외부 AI API를 호출하지 않는다. 학습자가 직접 선택한 도구를 쓰는 활동은 선택 과제로 둔다.
- 풀이 기록은 기존처럼 브라우저 안에 저장하고 백업·복원 경로를 유지한다.
- 인증, 서버, 클라우드 데이터베이스, 결제, 분석 추적기는 필요성과 비용·개인정보 결정을 새로 기록하기 전까지 추가하지 않는다.
- 공개 배포와 로컬 개편을 분리한다.

## 학습 모델

각 핵심 역량은 여섯 단계로 표시한다. 단계 이름은 기술 트랙의 실제 선수 관계에 맞게 조정하되, 모든 단계에 확인 가능한 수행 과제를 둔다.

1. 기초 이해: 용어와 실행 규칙을 자기 말로 설명한다.
2. 흐름 추적: 입력부터 결과까지 상태와 실행 순서를 예측한다.
3. 응용: 요구사항이 바뀐 문제에 기존 개념을 적용한다.
4. 진단: 잘못된 동작의 원인과 영향을 코드·출력·요구사항 근거로 찾는다.
5. 검증·개선: 테스트를 만들고 안전하고 읽기 쉬운 수정안을 제시한다.
6. 설계·유지보수: 여러 대안을 비교하고 성능, 보안, 호환성, 운영상 절충을 설명한다.

주제마다 필요한 수행 수준이 다르므로 모든 언어에 같은 문항 수나 같은 주차를 강제하지 않는다. 공통 역량을 기준으로 기술별 경로, 예제, 실행 가능 범위, 평가 방식을 매핑한다.

## 단계별 실행 순서

### 0단계 — 목표와 화면 기준 정리

- 공통 역량표를 만들고 현재 12개 트랙의 목표·선수 지식·문항 유형·검증 범위를 연결한다.
- 개념을 안다고 판단할 증거를 정한다: 말로 설명하기, 결과 예측, 다른 조건 적용, 오류 근거 찾기, 테스트로 수정 검증하기.
- 화면 디자인 초안을 DESIGN.md에 기록한다. 현재 CSS 규칙과 충돌하는 변경은 초안과 실제 적용을 구분한다.

완료 기준: 역량표와 과정 연결 기준, 화면의 정보 구조, 접근성 기준을 문서로 검토할 수 있다.

### 1단계 — 메인 화면과 기술 탐색 재설계

- 첫 화면의 중심을 오늘의 한 가지 학습 행동에 둔다.
- 이어서 공부하기와 최근 활동을 진도에 따라 보여준다.
- 저장된 풀이 시각으로 학습 기록 격자를 만들고, 하루를 선택하면 정확한 날짜와 활동 수를 표시한다. 기록은 사용자 기기에만 둔다.
- 활동 격자는 문제별 최근 풀이 날짜를 사용한다. 요약 기록은 학습 문제 10,000개, 코딩 문제 5,000개까지 보존하고, 필요할 때 기존 답안 기록으로 보완한다. 최근 12주를 보여 주며 보존된 기록이 그보다 짧으면 실제 시작 날짜를 표시한다. 모든 재시도 기록이나 평생 잔디가 필요한지는 별도 기록 형식 검토 후 정한다.
- 기술 탐색은 데스크톱에서 시각적인 기술 궤도 메뉴로 제공한다. 포인터 올림, 키보드 포커스, 클릭에서 열리고 메뉴를 닫을 수 있다. 모든 항목을 목록으로도 제공하며, 모바일에서는 누르면 두 열의 세로 목록이 열린다.
- 오늘의 짧은 예제는 현재 이어갈 경로의 다음 개념을 사용한다. 중복 정보가 되면 생략하고 시작 버튼을 분명히 둔다.

1단계 구현에는 이어하기, 최근 12주 활동 격자, 예제 미리보기, 12개 기술 경로 메뉴가 들어갔다. 내부 브라우저에서 320·390·480·768·1280px 메인 화면, 모바일 목록, 키보드 날짜 선택, 메뉴 닫기와 초점 복귀, 저장된 화면 전환, 문제·코딩·경로·수업·기록 화면의 주요 배치를 확인했다. 768px에서 메인 활동과 예제가 눌리는 것을 발견해 세로 배치로 바꾸고 다시 확인했다. AI 문제의 세금 계산기·스팸 분류기는 각각 이름과 설명이 분명한 행으로 보인다. 후속 화면 검토에서 오늘의 예제가 미완성 코딩 문제를 그대로 보여 주고 기록 격자의 폭을 활용하지 못하는 점을 고쳤다. 코딩을 이어갈 때는 현재 문제 주제에 맞는 미완료 학습 예제를 먼저 보여 주며, 이미 학습한 주제라면 관련 예제를 복습용으로 선택한다. 연결된 주제가 없으면 활성 학습 경로의 다음 단원을, 경로를 마쳤으면 완료한 가장 높은 단원을 보여 준다. 코드는 구문 강조·줄 번호가 있는 코드 블록으로 보인다. 기록 격자는 영역 폭을 채우도록 바꾸고 320·493·1280px에서 확인했다. 실제 초보 학습자 관찰은 하지 않았으므로 사용자 연구가 완료된 것으로 보지 않는다. 단계별 구현·검증 증거는 [진척 기록](progress.md)에 있다.

완료 기준: 처음 방문한 학습자도 다음 행동과 기술 찾기를 쉽게 발견하며, 기존 학습자는 저장된 위치로 한 번에 돌아간다. 모바일·키보드 조작이 데스크톱과 동등하다. 기록 격자가 보여주는 기간은 실제 저장 범위와 일치한다.

### 2단계 — 수업 화면과 연습 흐름 개선

각 단원은 아래 흐름을 상황에 맞게 조합한다.

1. 학습 목표와 선수 개념을 쉬운 문장으로 안내한다.
2. 완성된 예제로 핵심 원리를 설명하고, 필요하면 대조 예제를 함께 보여 준다.
3. 학습자가 실행 결과나 상태 변화를 먼저 예측하게 한다.
4. 개념 확인, 코드 추적, 요구사항 변경, 오류 진단, 코드 수정, 테스트 선택 문제를 섞는다.
5. 힌트는 다음 추론을 돕고, 해설은 정답뿐 아니라 근거와 잘못된 접근이 실패하는 이유를 설명한다.
6. 마지막에는 조건이 달라진 문제로 배운 개념을 옮겨 보게 한다.

완료 기준: 문항 완료 수만으로 숙달을 표시하지 않고, 핵심 목표가 다른 형식과 새로운 상황에서 확인된다.

### 3단계 — JavaScript 실무 경로를 기준 과정으로 검증

- 기초 값·조건·반복·함수·배열·객체부터 범위·비동기·모듈·브라우저·HTTP/API·테스트·오류 처리·보안·성능·접근성·리팩터링·유지보수까지 선수 순서로 연결한다.
- 예제는 결과만 보여주는 코드와 실제로 실행·검증하는 코드를 분리해 표시한다.
- 문제는 예측, 직접 구현, 기존 코드 읽기, 결함 찾기, 테스트 작성, 요구사항 변경을 고르게 포함한다.
- 코드 작성 문제는 함수 계약, 경계 입력, 예상 결과와 자동 평가 기준을 맞춘다.

완료 기준: JavaScript의 한 핵심 경로에서 목표→설명→예제→여러 유형의 문제→해설→실무형 누적 과제가 이어지고, 새 상황에 적용하는 평가가 있다.

### 4단계 — AI 이해와 AI 보조 개발 역량 연결

기존 27주 AI·LLM 이론 과정을 활용하면서 개발자 업무에 맞는 실습을 잇는다.

- 프롬프트: 목표, 맥락, 입력, 제약, 출력 형식, 평가 기준을 명시하고 결과를 비교한다.
- 답변 검증: 출처 확인, 수치·API 사실 점검, 반례와 불확실성 찾기를 연습한다.
- 코드 리뷰: 의도적으로 잘못된 AI 코드를 제공하고 요구사항 불일치, 경계값, 오류 처리, 보안, 성능, 불필요한 복잡성을 찾는다.
- 보완: 결함을 재현하는 테스트를 만들고 수정 뒤 같은 테스트와 경계 테스트를 실행한다.
- 사용 판단: AI를 쓰지 않는 편이 나은 일, 사람의 검토가 필요한 일, 민감한 자료를 보내면 안 되는 경우를 구분한다.

완료 기준: 정답 문구만 맞히지 않고 결함 위치와 이유, 재현 조건, 테스트 증거, 수정 효과를 설명한다. 실습은 외부 AI API 연결 없이 정적 사례와 사용자가 선택한 도구로 제공한다.

### 5단계 — 공통 실무 지식과 나머지 기술 경로 확장

- 리팩터링, 메모리와 자원 관리, 네트워크·HTTP, 트래픽 제어, 캐시·속도 제한·대기열·부하 분산, 데이터베이스, 보안, 운영·관측 가능성을 공통 역량으로 정리한다.
- 각 주제는 공통 개념을 먼저 배우고 JavaScript, Python, Java, 웹 프레임워크, 데이터베이스 등 기술별 차이를 뒤에서 비교한다.
- 모든 언어·기술에 같은 예제를 복제하지 않는다. 실행 모델과 생태계에 맞는 현장 사례를 사용한다.
- 기존 트랙을 역량표에 매핑해 빈 부분, 중복, 선수 지식 오류를 찾아 순서대로 보완한다.

완료 기준: 트랙마다 무엇을 알고 무엇을 할 수 있는지 분명하며, 개념 전용 예제와 실행 검증된 예제를 혼동하지 않는다.

### 6단계 — 범위를 고정한 검증과 출시 판단

- 변경한 콘텐츠 구간의 정답·해설·예제·목표 정합성을 전용 검사와 직접 대조로 확인한다.
- 핵심 여정(첫 방문, 경로 선택, 오늘 학습, 답 제출, 해설, 재개, 기록 백업)을 내부 브라우저에서 확인한다.
- 320, 390, 768, 1280px와 밝은·어두운 화면, 키보드·터치 동작을 확인한다. 마우스 확대 검사는 우선순위에서 제외한다.
- 가능하면 초보 학습자의 동의를 얻어 과제 수행을 관찰하고, 설명 이해·새 문제 적용·AI 코드 결함 발견 여부를 본다. 참여자가 없으면 전문가 점검으로 기록하고 사용자 검증 완료라고 쓰지 않는다.
- 단계별로 새 오류를 닫고 해당 범위를 종료한다. 변경이 모인 마지막 통합 시점에 전체 회귀를 한 번 실행하며, 새 근거 없이 같은 화면과 검사를 반복하지 않는다.

완료 기준: 실제 검수 범위와 한계가 문서에 남고, 완료된 구간과 미검증 구간이 분명하며, 공개 배포 전 사용자가 무엇을 기대할 수 있는지 과장하지 않는다.

## 우선순위

1. 목표·역량표와 학습 평가 기준
2. 메인 화면, 오늘 할 일, 이어하기, 로컬 기록 격자, 기술 탐색
3. 수업·문제 화면의 예제와 피드백 흐름
4. JavaScript 실무 경로와 AI 생성 코드 검토 실습
5. 공통 실무 지식 및 나머지 언어·기술 경로
6. 한정된 브라우저·콘텐츠 검증과 출시 준비

## 추적과 완료 보고

각 단계는 이 문서에서 완료 조건과 검증 근거를 갱신하고, 실제 작업 결과는 docs/plan/progress.md에 날짜와 함께 기록한다. 콘텐츠 범위와 디자인을 완료율 하나로 뭉뚱그리지 않는다. 사이트에 표시되는 완료 단계는 실제 검수 증거가 있는 범위만 반영한다.
