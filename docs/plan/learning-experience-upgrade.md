# 학습 경험 고도화 계획

- 작성일: 2026-10-11 (Asia/Seoul)
- 상태: 완료 — 2026-10-11 로컬 구현·검증·독립 리뷰 통과; 공개 재배포는 별도 작업
- 근거: 사용자가 현재 디자인과 가독성, 다섯 트랙의 얕은 기초 콘텐츠를 개선하고 단계별 고급 학습까지 확장해 달라고 요청함.
- 관련 기준: `DESIGN.md`, `docs/rules/design.md`, `docs/rules/content.md`, `docs/rules/architecture.md`

## 목표

학습 화면을 읽기 편한 편집형 학습 공간으로 다시 설계하고, JavaScript·Python·Java·Spring Boot·React 다섯 트랙을 입문부터 고급 실전까지 차례로 공부할 수 있게 확장한다. 계정, DB, 서버, 유료 API, 결제, 새 런타임 의존성은 추가하지 않는다. 학습 기록은 기존처럼 브라우저에 저장하고 백업/복원을 지원한다.

## 완료 기준

- 다섯 트랙마다 5개 숙련 단계(입문, 기초, 중급, 고급, 실전)를 제공한다.
- 각 트랙은 12개 학습 단원, 각 단원은 서로 다른 3개 풀이 활동을 제공한다. 총 60단원·180문항이다.
- 문제는 개념 확인, 실행 흐름 읽기, 오류 진단, 코드 수정, 적용 문제를 섞고 각 문항에 자체 정답 기준·힌트·해설이 있다. JavaScript에서만 기존 브라우저 Worker 실행 문제를 제공한다.
- 선수 관계와 현재 학습 단계·문제 번호가 분명하다. 단계는 점수로 잠그지 않고 언제든 다시 방문할 수 있다.
- 문제별 답안·초안 저장, 이어 풀기, 단원/트랙 진도, 백업/복원이 유지된다. 단원 완료는 세 문항을 모두 정답으로 마친 때 표시한다.
- 디자인은 밝은/어두운 테마에서 본문 16px 이상, 일반 UI 14px 이상, 문제 문장 17px, 코드 14px, 주요 버튼 높이 44px 이상을 지킨다.
- 홈, 트랙, 단계, 단원, 문제 흐름에서 장식 카드와 작은 영문 라벨을 걷어내고 다음 행동 하나가 분명하다.
- 작은 화면 레이아웃 자동 검사와 현재 브라우저 527px 화면 점검을 통과하고, 키보드 이동·포커스 표시·WCAG AA 대비·기기 설정/라이트/다크를 확인한다. 이 세션에서 강제한 실제 브라우저 뷰포트는 527px이며 320/390/768/1280px 개별 렌더 캡처는 수행하지 않는다.
- 새 콘텐츠의 공식 기술 출처와 검토 날짜가 기록되고, 정적 빌드와 자동 콘텐츠 검증이 통과한다.

## 단계별 교육과정 범위

각 트랙은 아래 12개 단원을 5개 숙련 단계로 묶는다. 학습 단원은 설명·완결된 예제·목표와 연결된 세 문항을 갖는다.

| 트랙 | 입문 | 기초 | 중급 | 고급 | 실전 |
|---|---|---|---|---|---|
| JavaScript | 변수·상수; 조건 **(2)** | 배열 순회; 함수 결과 **(2)** | 배열 함수; 객체; 범위·클로저 **(3)** | 모듈·오류·테스트; DOM·폼; Promise·fetch **(3)** | 이벤트 루프; 학습 통계 기능 설계 **(2)** |
| Python | 변수·값; 조건 범위 **(2)** | 리스트 순회; 함수 결과 **(2)** | 리스트 평균; 키 조회; 모듈·예외 **(3)** | 파일·컨텍스트 관리자; 제너레이터; 객체·타입 힌트 **(3)** | 비동기 작업; 학습 기록 요약 **(2)** |
| Java | 정수형; 조건 분기 **(2)** | 반복 범위; 합계 메서드; 생성자 초기화 **(3)** | 인터페이스·record; 제네릭 컬렉션; 예외 처리 **(3)** | 람다·스트림; 동시성·테스트 **(2)** | JVM 성능 측정; 알고리즘 적용 **(2)** |
| Spring Boot | 의존성 주입; 서비스 경계; 프로파일 설정 **(3)** | GET 연결; 요청 검증; REST 오류 **(3)** | 트랜잭션; 요청 보안; 통합 테스트 **(3)** | 시간 제한·캐시; 로그·지표·추적 **(2)** | API 계약·운영 검토 캡스톤 **(1)** |

모든 단계 수는 12개 단원이 되도록 맞췄다. 괄호의 숫자는 단계별 단원 수이며 각 행의 합은 12다.

## 구현 순서

1. **설계 기준 갱신** — root `DESIGN.md`에 대상 학습자, 시각 방향, 화면 구조, 최소 글자 크기, 상호작용/반응형 기준을 확정한다.
2. **콘텐츠/연습 구조 확장** — 단원 당 다중 문항, 개별 문항 경로와 기록, 정답 세 개 기반 완료 상태, 기존 v1 기록/백업 호환을 설계한다.
3. **학습 경로 탐색 개편** — 5단계와 단계별 단원·문항 수·선수 흐름을 보여 주고 단계/단원 목록을 읽기 쉬운 목차로 바꾼다.
4. **문제 풀이 개편** — 단원 안에서 문항 번호, 이전/다음, 초안 저장, 유형, 힌트/해설, 정답 상태를 제공한다.
5. **콘텐츠를 트랙별로 확장** — 기존 문항을 검수해 유지하고 부족한 단원을 보충한다. 단계별 12단원/36문항 기준을 먼저 충족한 트랙만 완료로 표시한다.
6. **편집형 디자인 적용** — 홈·트랙·단계·단원·문제·기록 화면의 정보 우선순위, 타이포그래피, 표면, 색상 토큰을 통일한다.
7. **전수 검증과 문서 갱신** — 문항별 정답/오답, 기존 기록 복원, 반응형, 다크 모드, 키보드, 버전·출처, 빌드·배포 경계를 확인한다.

## 문제 품질 규칙

- 각 단원은 개념 확인, 코드/상황 추적, 실제 적용 중 서로 다른 사고 동작 세 개를 다룬다. 같은 문제의 숫자나 변수명만 바꾸어 개수를 채우지 않는다.
- 객관식은 모든 보기마다 왜 맞거나 틀리는지 설명한다. 주관식은 엄격하고 검토된 허용 답을 쓴다. 코드 오류 찾기는 잘못된 줄과 이유를 일치시킨다.
- 정적 코드 수정은 해당 문항 전용 전체 함수/메서드 패턴으로 검증하고 실행했다고 말하지 않는다. 고정된 패턴으로 설명할 수 없는 요구는 객관식·코드 추적·설계 선택으로 평가한다.
- Spring Boot와 React 코드는 실행 프로젝트가 아닌 예시/분석 코드임을 표시하고, 없는 DB·외부 서비스·의존성 설정을 있는 것처럼 가정하지 않는다.
- 언어/프레임워크 버전 민감 내용은 공식 문서의 특정 버전을 참고하고, preview 기능은 안정된 기능과 분리한다.

## 최종 정리 계획

- 행동 기준선: `npm test`의 문항·진도·테마·저장·라우팅·릴리스 검사가 통과한 상태에서만 정리한다. 정리 뒤 같은 검사를 다시 실행한다.
- 정리 순서: 불필요한/죽은 코드 → 중복 → 이름과 오류 안내 → 필요한 회귀 검사 순으로, G10 변경 파일에 한정한다. 중복 단계 순서와 주제 메타데이터는 제거하고 실제 확장 자료를 단일 원본으로 정리했다.
- 대체 경로 검토: IndexedDB 실패 시 브라우저 로컬 저장소를 쓰는 경로는 오프라인 복구 경계이므로 오류를 숨기지 않는지 확인하고, 객관식 ID 연결은 백업 호환성을 위해 유지한다.
- 화면 검토: 작은 글자, 의미 없는 장식, 과도한 카드/색상, 중복 안내를 확인하되 브랜드·접근성·문제 풀이 명료성에 필요한 요소는 남긴다.
- 범위 경계: 독립 코드 리뷰와 아키텍처 리뷰에서 요청 범위 밖 변경이나 새 패키지를 추가하지 않는다.
