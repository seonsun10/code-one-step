## 1. 목표와 사용자 요구

학습 경로 안의 개념 문제와 별도로 **코딩 문제 메뉴**를 만든다. 학습자는 언어·난이도·주제에 맞는 문제를 선택하고, 예제와 요구사항을 읽은 뒤 코드 편집기에서 답안을 작성하고 실행 결과를 확인한다. 문제에 등록된 모든 채점 사례를 통과하면 해결로 기록한다. 사용자가 작성한 변수명, 공백, 주석, 알고리즘이 달라도 요구한 결과가 같으면 정답으로 인정한다.

언어와 프레임워크 학습에 공통으로 필요한 Git, 터미널, HTTP/API, SQL, 테스트, 디버깅 같은 **공통 실무 기초**도 별도의 순차 실습 과정으로 제공한다. 한 번에 주제를 넓히기보다 선수 개념부터 실습·복습·통합 과제로 이어지고, 각 단계가 검수된 뒤 다음 단계를 추가한다.

학습 기록은 현재처럼 브라우저 안에 저장한다. 비용이 발생할 수 있는 서버 실행, DB, 계정, 자동 동기화, 결제, 원격 코드 실행 서비스는 이 계획에 포함하지 않는다. 브라우저에서 실행할 언어는 기술·성능·라이선스·보안 조건을 통과한 경우에만 추가한다. 조건을 충족하지 못하면 실행을 지원하는 척하지 않고 코드 읽기·수정·결과 추적 등 실행 없는 실습을 제공한다.

현재 로컬 CP-9 공통 실무 과정은 26주(130회·390문제) 전체가 학습 가능하다. CP-10에서는 TypeScript·SQL/PostgreSQL·FastAPI의 검증된 실행 채점과 Next.js·Kotlin/Android·C#/.NET 무료 정적 학습 과정을 연결했다. Next.js는 33주·495개, Kotlin·Android는 31주·465개, C#·.NET은 35주·525개의 코드 읽기·개념·설계 판단 연습을 제공한다. 정적 학습 문항은 실제 실행·컴파일·APK·에뮬레이터 결과로 채점하지 않는다고 화면에서 알린다. 사용자는 실행이 어려운 기술에 실행형 문제 은행을 억지로 만들지 말고 무료로 가능한 범위만 제공하라고 정했다. FastAPI 런타임 및 문제는 브라우저 Worker·실제 문제 화면·릴리스 경계를 확인했다. CP-11에서 자동 검사, release 경계, 사용자 흐름, 데스크톱·390px 화면, 테마·키보드, 빈 결과·잘못된 문제 경로, 문서 정합성을 확인했다. C# 14는 .NET 10에서 지원되는 안정 언어이며 .NET 10.0.13 LTS를 2026-10-14 기준으로 연결했다. CP-10·CP-11과 CP 전체는 각각 100%다. 전체 과정과 실행기 변경은 공개 배포하지 않았다.

## 2. 현재 기반과 기존 계획의 관계

2026-10-14 기준선 및 현재 로컬 작업 트리:

- 기존 다섯 트랙(JavaScript, Python, Java, Spring Boot, React)은 주 5일·26주·트랙당 390문항 과정이다. CP-10에서 TypeScript 26주·390문항, PostgreSQL 39주·585문항, FastAPI 30주·450문항, Next.js 33주·495문항, Kotlin·Android 31주·465개, C#·.NET 35주·525개의 학습 연습을 별도 추가했다. Next.js·Kotlin·Android·C#·.NET 연습은 코드 읽기·개념·설계 판단용이며 관련 서버, 컴파일러, 앱 실행이나 결과 채점은 제공하지 않는다. 관련 메타데이터는 [src/content.js](../../src/content.js)와 주차별 콘텐츠 파일에 있다.
- CP-0 기준선 당시 별도 코딩 문제 메뉴는 없었다. CP-3에서 로컬 메뉴와 상세 풀이 화면을 연결했고 CP-5에서 JavaScript 문제 은행을 50개로 확장했다. 현재 검수·실행 승인을 마친 문제는 입문·기초·중급·고급·실전 각 10개이며 각 문제에 최소 여섯 공개 사례가 있다. 전체 사례를 사용하는 정답 코드 품질 검사는 [tests/coding-problem-quality.test.js](../../tests/coding-problem-quality.test.js)에 있다. CP-6·CP-10 실행 판정에서 승인된 실행 경로가 없는 Python·Java·Spring Boot·React·Next.js·Kotlin/Android·C#/.NET에는 결과 채점 문제를 제공하지 않는다. 필요할 때 무료 정적 학습 연습으로 다룬다.
- 제한 실행 경계는 [src/runner.js](../../src/runner.js)와 [public/runner-frame.html](../../public/runner-frame.html)에 있다. 브라우저 실행은 완전한 보안 샌드박스가 아니며, 공개 정적 파일에 둔 사례를 비밀 테스트로 간주할 수 없다.
- 학습 진도·답안·코드 초안은 [src/progress.js](../../src/progress.js)와 기존 저장 계층에서 브라우저 안에 기록하고 JSON 백업을 지원한다. 계정이나 기기 간 자동 동기화는 없다.
- 코드 편집기와 실행 결과 계획(CEX)은 CodeMirror 편집, JavaScript 실행 결과, 반환값 비교 규칙 및 언어별 실행 가능성 검토를 다룬다. 최신 기준은 [코드 편집기·실행 계획](code-editor-and-execution.md)과 [진척 관리](progress.md)다.
- G11은 기존 다섯 트랙의 장기 교육과정과 콘텐츠 검수를 다룬다. 그 계획은 [심화 교육과정 계획](curriculum-depth-upgrade.md)에 있다. 현재 공개 카탈로그와 미배포 로컬 과정의 구분은 출시 전 확인해야 한다.
- 공개 배포 기록상 2026-10-10 마지막으로 확인한 앱 카탈로그는 다섯 트랙 총 23개 단원이다. G10의 60개 단원·180문항, G11의 650회 학습 세션·1,950문항, CEX CodeMirror 편집기와 실행 채점은 현재 로컬 변경이며 공개 배포하지 않았다. 공개 URL의 실시간 상태는 배포 전에 다시 확인한다.

### 계획을 따로 두는 결정

이번 범위는 기존 CEX의 편집기·실행기 기술 작업이나 G11의 다섯 교육과정 보강과 다르다. 독립 메뉴·검색·도전 문제 데이터·실무 기초 교육과정·추가 언어 확장을 포함하므로 **CP라는 별도 계획으로 관리**한다. 기존 G1–G11과 CEX의 완료율을 소급 변경하거나 합산하지 않는다. CEX는 CP가 재사용할 편집기·실행기 기반이며, G11은 학습 경로와 진행 기록의 기존 모델로 참조한다. 계획과 기능 진척의 숫자는 docs/plan/progress.md에서 서로 분리한다.

## 3. 제품 흐름과 범위

### 코딩 문제 메뉴

1. 상단 주요 탐색에서 코딩 문제를 바로 연다.
2. 목록에서 언어, 난이도, 주제, 예상 시간, 미풀이·풀이 중·해결·복습 상태를 좁힌다.
3. 문제에서 목표, 입력/출력 또는 함수 계약, 제약, 입출력 예제, 시작 코드, 편집·실행 안내를 확인한다.
4. 질문/예제, 코드 편집기, 실행·테스트 결과, 해설은 제목과 색/경계가 다른 독립 영역으로 표시한다. 넓은 화면에서는 문제와 편집 결과를 나눠 보고, 모바일에서는 읽기 순서대로 세로로 이어 본다.
5. 코드를 실행해 표준 출력, 반환 결과, 각 사례의 기대값과 실제값, 통과/실패 및 오류를 구분해 본다.
6. 등록된 채점 사례가 모두 통과하면 문제를 해결로 기록하고 풀이 설명과 다음 문제를 연다. 실패하면 사례별 설명과 단계별 힌트를 보고 다시 실행한다.
7. 다시 방문하면 마지막 필터, 문제 위치, 작성 중 코드와 풀이 상태를 같은 브라우저에서 이어간다.

확정 경로는 `#/coding`, `#/coding/:language`, `#/coding/problem/:problemId`, `#/foundations`, `#/foundations/:unitId`다. 상세 구현 전제와 정보 계층은 저장소 루트 [DESIGN.md](../../DESIGN.md)의 정보 구조를 기준으로 한다.

### 목록과 이어하기 정보 구조

- 데스크톱 주요 탐색은 `내 학습실`, `배울 주제`, `코딩 문제`, `공통 실무 기초`, `내 기록` 다섯 항목이다.
- 모바일 하단 탐색은 `홈`, `학습`, `코딩`, `실무`, `기록` 다섯 항목이며, 전체 접근성 이름은 각각 `내 학습실`, `배울 주제`, `코딩 문제`, `공통 실무 기초`, `내 기록`이다. 폭 320px에서도 44px 이상의 조작 영역과 전체 접근성 이름을 유지한다.
- 코딩 문제 목록은 현재 문제 은행에서 실제로 제공하는 언어·난이도·주제만 선택지로 구성한다. 검색어와 풀이 상태(미풀이·진행 중·해결·복습)를 조합할 수 있으며 필터 적용 후 결과가 없으면 이유와 필터 초기화 동작을 제공한다.
- 문제 목록 항목에는 제목, 언어, 난이도, 주제, 예상 시간, 풀이 상태를 보여 준다. 실행 가능 여부와 학습 가능 여부를 별도 상태로 표시한다. 아직 런타임이 없는 언어의 문제는 실행 없는 풀이 방식을 표시하고 실행 버튼을 노출하지 않는다.
- 공통 실무 기초는 주차·실습일 순서, 선수 조건, 학습 목표, 예제, 실습 결과물, 세 연습의 상태를 보여 준다. 아직 작성/검수가 끝나지 않은 주차는 준비 중 상태로 표시하며 완성된 콘텐츠처럼 세지 않는다.
- CP-3 필터는 현재 페이지에서 즉시 조합·초기화할 수 있다. CP-4에서 코드 초안·풀이 기록·마지막 문제 위치·목록 필터를 기존 학습 기록과 분리해 브라우저에 보존하고 v1 백업을 v2로 변환한다. IndexedDB DB/store 구조는 그대로 둔다. 자동 저장 경계·백업 왕복 검사와 CP-11의 실제 브라우저 코드/6개 결과 재진입 확인을 통과했다.
- 와이드 화면 문제 풀이는 지문/예제와 편집기/결과를 나란히 보이되 서로 다른 영역으로 구분한다. 모바일은 지문 → 예제 → 편집기/실행 → 사례 결과 → 힌트/풀이 → 다음 문제 순서로 쌓는다. 키보드 순서는 화면 읽기 순서와 일치한다.

### 공통 실무 기초

언어별 문법에 종속되지 않는 실무 작업을 짧은 개념 안내와 로컬 실습으로 배운다. 학습 기록은 기존처럼 같은 브라우저에서 재개한다. 처음부터 외부 GitHub 계정, API 키, 데이터베이스 계정, 결제 계정이나 클라우드 가입을 요구하지 않는다.

장기 과정 목표는 기존 콘텐츠 규칙에 맞춰 **26주·주 5일·하루 세 개의 서로 다른 연습(130회·390문항)**으로 둔다. 각 실습일에는 목표, 예시, 직접 해 보는 작업, 확인 기준과 복습 설명이 있어야 한다. 26주 전체가 검수되기 전에는 완성된 과정으로 표시하지 않는다.

기존 각 트랙에는 G11의 장기 학습 경로가 이미 있지만, 별도 코딩 문제 메뉴의 실행 문제 은행은 별도 콘텐츠다. 실제 입력 코드 실행과 결과 채점 gate를 통과한 프로그래밍 언어만 입문·기초·중급·고급·실전 각 10개씩, **언어당 최소 50개의 서로 다른 결과 채점 문제**를 목표로 한다. 무료·정적 환경에서 실행이나 채점이 어려운 언어·프레임워크에는 이 문제 은행을 강제하지 않는다. 학습 목표에 맞고 무료로 검수 가능한 경우 코드 읽기·개념·오류 분석·설계 판단 연습으로 대체하며, 이런 연습은 실행 결과 채점 문제와 구분한다. 프레임워크 시나리오도 실제 동작을 검증할 수 있을 때만 결과 채점으로 표시한다.

### 이번 계획에 포함하지 않는 기능

- 회원 가입, 계정별 클라우드 저장, 자동 기기 동기화, 데이터베이스, 분석 추적, 결제·구독, 유료 잠금.
- 정적 사이트 코드에 정답 데이터가 공개되는데도 숨겨진 테스트나 부정행위 방지라고 표현하는 기능.
- 비용·보안·개인정보 검토 없이 서버에서 임의 사용자 코드를 실행하는 기능.
- 학습 콘텐츠를 자동 생성해 검수 없이 게시하거나 버전 최신성을 보장한다고 말하는 기능.
- 사용자 수요 확인 전 순위표, 소셜 피드, AI 튜터 등 학습 핵심 흐름 밖의 기능.

## 4. 콘텐츠·채점 데이터 기준

새 문제는 화면 컴포넌트에서 분리해 검색·검수 가능한 자료로 관리한다. CP-2는 `src/coding-problems.js`의 카탈로그와 `scripts/coding-problem-schema.mjs`의 무의존성 빌드/검사 도구를 기준으로 한다. 검증 도구는 배포 파일에 넣지 않는다. 기존 학습 화면은 같은 문제 항목을 연결하며 별도 복제하지 않는다.

각 문제에 필요한 정보:

- 고유 ID, 제목, 설명, 언어/프레임워크와 버전, 숙련 단계, 주제 태그, 선수 문제, 예상 시간.
- 하나의 검증 가능한 학습 목표, 요구사항, 제약, 함수 계약 또는 입력/출력 형식, 예제 입력과 예제 결과.
- 시작 코드, 실제 실행이 가능한지 여부, 등록된 실행 어댑터 ID와 입출력 방식. 어댑터가 실제 적용하는 시간·입력·출력 한도는 그 어댑터 계약에서 관리하며 자료 검사는 사례 크기·개수와 코드 길이의 상한을 확인한다.
- 채점 사례별 입력·기대 결과·비교 방법. 정답 코드 문자열을 비교하지 않는다.
- 단계형 힌트, 풀이와 복잡도/설계 설명, 흔한 오답 이유, 연관 학습 단원과 공식 출처.
- 작성자 검토 상태, 기술 버전 확인 날짜, 난이도/중복 검수 상태.

### CP-2 데이터 계약

각 자료는 `id`, `title`, `language`, `framework`, `versionContext`, `level`, `topicIds`, `prerequisiteIds`, `estimatedMinutes`, `objective`, `statement`, `requirements`, `constraints`, `contract`, `examples`, `starterCode`, `runtime`, `grading`, `hints`, `solution`, `sources`, `review` 필드를 사용한다. 필수 문자열·길이·ID·정렬 수준·예상 시간과 날짜를 검사한다. 출처는 HTTPS여야 하고 승인 문항은 검수 날짜를 가져야 한다.

- 함수 계약은 `contract.kind: function`, 유효한 `entryPoint`, 입력/출력 설명을 사용한다. 표준 입력 계약은 `kind: stdin`과 문자열 입력을 사용한다. 실행 없는 시나리오는 `kind: scenario`로 구분한다.
- 학습자에게 보이는 `examples`와 결과를 비교하는 `grading.tests`는 분리한다. 함수 입력은 JSON 인자 배열, 표준 입력은 문자열로 고정한다. 입력·기대값은 유한 숫자, 문자열, 불리언, null, 배열, 일반 객체만 허용하며 깊이와 전체 사례 크기를 제한한다.
- 검수된 자동 실행은 `runtime.status: verified` 및 알려진 로컬 `adapterId`와 `grading.mode: runtime-output`를 함께 가져야 한다. CP-2에서 승인된 어댑터는 기존 격리 실행기 기반의 `javascript-function-v1` 하나다. 함수 반환 비교는 타입을 포함한 재귀 구조 비교이며 객체 키 순서는 무시하고 배열 순서는 유지한다. stdout 비교는 후속 어댑터가 실제 지원할 때만 정확한 문자열 비교로 추가한다.
- 실행을 지원하지 않는 언어는 `runtime.status: unavailable`, `mode: none`, `adapterId: null`, `grading.mode: guided`와 구체적인 자기 점검 기준을 사용한다. 이 상태를 자동 실행·통과로 표시하지 않는다.
- 빈 문제 은행, 문제 ID 중복, 없는 주제/선수 문제, 선수 관계 순환, 알 수 없는 실행 어댑터, 예제와 테스트 결과 불일치, 테스트 누락/20개 초과, 64 KiB 초과 사례, 안전하지 않은 값, 잘못된 출처/검수 상태는 테스트 및 정적 빌드에서 거부한다. `npm run build`도 실제 문제 은행을 검사하며 검증 실패 시 배포 산출물을 만들지 않는다.

예제는 학습자가 동작을 이해하도록 보이는 예시이고, 테스트 사례는 제출 결과를 확인하는 기준이다. 정적 앱에서는 채점 자료를 역으로 볼 수 있으므로 모든 테스트는 공개 사례로 취급한다. UI에는 등록된 공개 사례를 모두 통과했다고 정확히 알린다. 비공개 정답을 서버에 두는 구조가 필요해지면 별도 보안·비용 결정이 선행되어야 한다.

채점기는 실행 방식과 정답 비교를 분리한다. 기본 비교는 원시 값의 타입과 값, 문자열의 정확한 값, 배열의 순서, 객체의 키·값을 확인하고 중첩 구조에도 같은 규칙을 적용한다. 문제에서 명시한 경우에만 개행 등 비교 규칙을 바꾼다. 표준 출력은 반환값과 별도 표시하고, 출력이 목표인 문제만 표준 출력을 명시적으로 채점한다.

## 6. 순서별 구현 계획과 가중 진척

각 CP 단계는 완료 조건과 증거가 함께 확인되어야 완료 처리한다. CP 계획 이행률은 단계별 가중치를 단계 완료율에 곱해 계산한다. CP-0부터 CP-9까지 완료했고 CP-9은 26/26주·130/130회·390/390문제다. **2026-10-14 사용자 범위 변경**으로, 무료 정적 사이트에서 실행 환경을 만들기 어려운 후보는 결과 채점 문제 은행을 필수로 하지 않는다. ### 새 언어·프레임워크별 완료 기준

- 새 언어/프레임워크의 학습 범위는 초급에서 고급·실전까지 선수 관계를 갖춘다. 장기 과정을 제공할 때는 주제와 목표에 알맞은 분량을 정하고, 26주·130회·390개는 계획 기준이지 모든 기술에 억지로 채워 넣을 할당량이 아니다. 실행 환경이나 검수 자료가 부족하면 확인 가능한 범위에서 학습 과정을 구성하고 제한을 표시한다. 공통 기초 과정은 링크해 다시 설명하는 양을 줄일 수 있지만, 그 트랙만의 문법·도구·실무 목표 연습을 대신 세지 않는다.
- 실제 입력 코드 실행과 결과 채점 gate를 통과한 언어는 5단계 각 10개, 총 50개의 결과 채점 문제를 1차 목표로 삼는다. 각 문항에는 최소 6개의 검수된 공개 사례, 예제, 힌트, 오답 이유, 정답 풀이가 있어야 한다. 정적 학습 트랙에는 이 실행 문제 할당량을 적용하지 않는다.
- 실행 지원은 CP-6의 크기·로딩·라이선스·격리·실제 입력 코드 실행 gate를 통과한 경우에만 표시한다. gate를 통과하지 못한 언어·프레임워크도 사용자 합의에 따라 단계별 코드 읽기·오류 분석·설계 판단 과정을 제공할 수 있다. 해당 문항 수는 결과 채점 문제와 분리해 세고, 실제 실행·컴파일·채점을 했다고 표시하지 않는다.
- Spring Boot·React·FastAPI·Next.js 같은 프레임워크는 독립 언어와 구분한다. 무료로 검수 가능한 경우에만 기능별 시나리오 연습을 제공한다. 프레임워크 동작을 실제 실행하지 못하면 결과 채점 문제라고 부르지 않고, 실행 없는 코드 읽기·설계 연습임을 화면에 표시한다.
- 완료된 확장 순서는 TypeScript → SQL/PostgreSQL → FastAPI → Next.js → Kotlin/Android → C#/.NET이다. Go/Rust는 수요와 무료 학습 가능 범위를 확인한 뒤 별도 결정한다. 각 트랙은 기술에 맞는 무료 학습 형태의 검수와 탐색·진도 연결을 마쳤다.

각 주의 다섯 일차는 서로 다른 목표를 가지며, 하루 세 연습은 개념 확인·안내 실습·응용/오류 찾기로 나눈다. CP-9에서 day별 목표·fixture·정답·오답 근거를 작성한다. Git merge와 SQL 변경은 브라우저에서 초기화 가능한 시뮬레이션으로 가르치며 실제 사용자 저장소·DB를 건드리지 않는다. 주별 완료는 진도 기록이며, 점수로 다음 주를 잠그지 않는다.

## 8. 무료 운영·보안·개인정보 조건

- 새 기본 기능은 정적 파일로 제공하고, 사용자 코드는 사용자 브라우저에서만 실행한다. 외부 실행 API, 서버 함수, DB, 계정, 동기화, 결제 연결을 추가하지 않는다.
- 기존 Worker·iframe 제한, CSP, 입력/출력 크기 제한과 시간 제한을 약화하지 않는다. Worker는 악성 코드에 대한 완전한 보안 경계라고 표현하지 않는다.
- 추가 실행기는 문제를 처음 열 때만 로컬 정적 파일에서 늦게 불러오고 홈 진입의 기본 다운로드를 늘리지 않는다. 압축·비압축 전송량, 초기 실행 시간, 캐시, 모바일 메모리, 배포 호스트 파일 제한을 측정한다. 제공처·업데이트·라이선스가 불확실하거나 제한을 넘는 후보는 실행기에서 제외한다.
- 사용자 코드를 외부로 보내지 않는다. 문제 테스트 사례와 교육 자료는 정적 배포 내용으로 공개될 수 있다고 가정한다.
- 기존 풀이/백업 스키마를 변경할 때 architecture.md의 버전·마이그레이션 규칙을 따른다. 기존 학습 진도와 초안을 유지하고 오래된 백업을 회귀 검사한다.
- 패키지를 검토할 때 공식 저장소/레지스트리, 무결성 잠금, 라이선스, 알려진 취약점, 실제 배포 파일 크기를 기록한다. 취약점 감사 결과를 바이러스 검사 또는 무위험 보증이라고 말하지 않는다.
- 도구가 필요 없는 과제는 서버 없이 가능하게 한다. 특정 운영체제/설치 경험이 필요한 과제는 대체 시나리오를 제공하고 학습 진도에서 불이익을 주지 않는다.

## 9. 콘텐츠 정확성 검수

코딩 문제와 실무 과제는 공개 전에 다음 기준을 모두 충족해야 한다.

1. 문제 요구사항·입출력 계약·예제·테스트 기대값·풀이 코드가 서로 일치한다.
2. 성공 사례뿐 아니라 빈 값, 최솟값/최댓값, 중복, 음수/0, 잘못된 입력처럼 문제 목표에 필요한 경계를 포함한다.
3. 각 테스트를 사람이 풀이와 대조하고, 런타임이 승인된 문제는 실제 실행기에서도 모든 테스트가 기대 결과를 낸다.
4. 변수명·공백·주석·대체 알고리즘이 달라도 결과가 맞으면 통과하는지 확인한다. 비교 정규화가 문제 조건을 지우지 않는지 검사한다.
5. 난이도는 언어 문법의 선수 순서를 반영하고 쉬운 변형만 늘려 문항 수를 채우지 않는다. 매일의 세 문제는 다른 사고 동작을 평가한다.
6. 오답 설명은 구체적인 원인과 다음 시도를 알려 준다. 힌트는 첫 단계부터 전체 정답을 노출하지 않는다.
7. 버전별 동작, API, 지원 종료 정보를 공식 자료·확인일과 연결하고 프리릴리스/preview를 안정판과 구분한다.
8. 자동 검사로 ID 중복, 누락 필드, 끊긴 선수 ID, 사례 없는 실행 문제, 기대값/풀이 누락, 검수 상태 오류를 차단한다.

## 10. 검증과 출시 순서

각 CP 단계가 바뀔 때 해당 범위만 검사하고, CP-11에서 전체 검사를 반복한다.

- **자료 검사:** 문제 ID 고유성, 필수 필드, 모든 실행 사례와 예제 결과 연결, 수준·주제 태그, 공식 버전 출처, 설명/힌트/정답 존재, 중복 문항 탐지.
- **채점 단위 검사:** 정상 정답, 의도적인 오답, 빈 코드, 다른 변수명/공백/주석의 동등 답, 타입/순서 차이, 객체 키 순서, 중첩 값, 오류와 시간 초과.
- **저장 회귀 검사:** 새 초안 저장, 다시 열기, 정답/오답 이력, 새로고침, v1 백업 복원, 손상된 백업 거부, 용량/저장 실패 경고.
- **브라우저 흐름:** 메뉴→필터→문제→예제 확인→편집→실행→사례 결과→모든 사례 통과→풀이 저장→다시 이어 풀기의 전체 경로.
- **언어 경계:** 미지원 런타임은 실행 버튼을 감추거나 명확히 대체 실습을 안내한다. Spring/Next.js 서버 동작을 브라우저 로컬 실행으로 오표시하지 않는다.
- **화면/접근성:** 320·390·768·1280px 이상, 키보드만 사용, 명시적 포커스, 화면 낭독기 이름, 라이트·다크 모드, 코드 선택 대비, 페이지 전체 가로 넘침 없음.
- **비용/출시 감사:** 런타임 외부 호출 없음, 패키지와 정적 파일 라이선스 고지, CSP·배포 크기·호스트 제한·비밀값/개인 기록 제외를 확인한다.
- 공개 사이트 업데이트는 이 계획의 로컬 구현 완료와 별도다. 공개 변경 전 현재 호스트 약관과 무료 한도를 다시 확인하고 별도 출시 절차를 기록한다.

## 12. 도움 필요 여부와 범위 변경 규칙

현재 계획을 작성하거나 첫 단계에 진입하는 데 사용자의 추가 결정은 필요하지 않다. 현재 합의된 무료·정적·계정 없는 제품 원칙으로 계속할 수 있다.

다음 요구가 생길 때만 별도 결정/도움 항목을 만든다.

- 비공개 정답·숨은 채점·악용 방지가 필요한 경우.
- Java/Python/Spring 등에서 서버 수준 실행이 필요하다고 확인된 경우.
- 계정, 자동 동기화, 클라우드 저장, 결제/구독을 추가하려는 경우.
- 선택 런타임/패키지가 무료 범위·브라우저 성능·라이선스·보안 조건을 벗어나는 경우.
- 운영 데이터나 사용자 로그를 외부에 전송해야 하는 경우.

지원되는 언어는 결과를 실제 실행해 테스트 사례로 채점한다. 다만 사용자가 2026-10-14에 범위를 명확히 해, 무료·정적 환경에서 프레임워크 실행이 어렵다면 실행형 은행을 만들지 않고 코드 읽기·오류 분석·설계 연습으로 학습을 제공할 수 있다. 이를 실행 채점 완료라고 표시하지 않으며, 실행 지원 여부는 별도 상태로 남긴다. 서버 실행이 유일한 경로가 되면 현재 무료·계정 없는 범위에 넣지 않는다.

해당 문제가 한 단계의 일부만 막으면, 그 항목만 보류하고 독립적으로 진행 가능한 콘텐츠·UI·자료 검사 단계는 계속한다. 잘못된 정답, 버전 정보, 도구 사용 오류가 발견되면 재현 내용·영향 범위·수정 근거를 decisions-and-help.md에 기록하고 해결 증거 후에만 단계 진척을 갱신한다.
