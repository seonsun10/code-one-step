## 1. 목표

문제의 코드 입력을 읽고 편집하기 쉬운 편집기로 바꾼다. 코드를 제출하면 실행 결과, 표준 출력, 오류, 통과한 테스트와 실패한 테스트를 각각 알아볼 수 있게 보여준다. 문제에서 요구한 동작과 결과가 맞으면 변수명·공백·주석·알고리즘의 작성 방식이 달라도 정답으로 인정한다.

시작 조건은 현재 프로젝트의 무료 정적 앱 경계를 유지하는 것이다. 계정, 앱 서버, 데이터베이스, 외부 코드 실행 서비스, 결제 기능은 추가하지 않는다. 사용자 코드와 학습 진도는 기존 브라우저 저장 흐름에 남긴다. 언어별 로컬 실행은 실행 가능한 것으로 확인된 트랙에만 제공한다.

## 2. 저장소에서 확인한 현재 동작

- 코드 작성·수정 문제는 CodeMirror 6 편집기에서 렌더링한다. JavaScript/JSX/TypeScript, Python, Java 문법 패키지를 정적으로 묶으며 줄 번호, 선택 줄, 구문별 색상, Undo/Redo, 자동 들여쓰기와 20,000자 입력 제한을 제공한다.
- CodeMirror 입력은 기존 숨김 textarea 어댑터와 연결되어 초안 저장·복원 흐름을 유지한다. 편집기 코드는 npm 잠금 파일에 고정한 MIT 패키지이며, 빌드 결과에는 번들과 타사 라이선스 고지를 넣는다.
- `src/main.js:654-677`은 코딩 문제를 실행하고 제한 시간·통과 수·표준 출력을 안내에 표시한다. 별도의 표준 출력/테스트 결과 패널은 없다.
- `src/runner.js:1-39`와 `public/runner-frame.html:5-64`는 제한된 iframe 안의 Web Worker에서 JavaScript 함수를 실행한다. 코드/출력 크기와 실행 시간이 제한되며 네트워크 기능을 차단한다. 이 경계는 완전한 악성 코드 격리가 아니다.
- `public/runner-frame.html:27-42`는 반환값을 JSON 직렬화 문자열끼리 비교한다. 객체 속성 순서가 다른 동등한 객체는 다르게 판정될 수 있다. 반면 코딩 답의 공백이나 주석은 반환 동작을 바꾸지 않는 한 테스트 입력에 영향을 주지 않는다.
- `src/grading.js`의 코드 수정 채점은 언어별 패턴으로 코드를 확인한다. 이 방식은 수정 문제에 계속 쓸 수 있지만, 실행 문제의 정답 판정은 코드 모양 대신 실행 결과 테스트를 기준으로 한다.
- `docs/rules/architecture.md:22-28` 및 `docs/rules/privacy-security.md:10-17`은 브라우저 자동 실행을 JavaScript로 제한하고, 다른 런타임·강한 격리는 별도 안전성·비용 검토 없이 추가하지 않도록 정한다.
- `docs/plan/content-roadmap.md:37-43`은 Python·Java·Spring Boot·React의 기존 문제를 정적 코드 읽기/수정 문제로 두고 JavaScript만 자동 실행 대상으로 설명한다.
- 이미 저장된 코드 초안은 `src/main.js:746-750`의 입력 이벤트로 보존된다. 새 편집기도 현재 초안 복원·진도 동작을 유지해야 한다.

## 3. 요구사항과 완료 기준

### 코드 편집 경험

- 편집 영역에 전체 언어 이름, 문법에 맞는 색상, 줄 번호, 현재 포커스·선택 상태를 제공한다. 라이트/다크 테마에서 편집 글자·배경·선택·커서 대비를 각각 유지한다.
- Enter로 새 줄을 만든 뒤 이전 줄의 들여쓰기를 이어간다. `{}`, `[]`, `()` 블록을 시작하면 한 단계 들여쓰고, 닫는 괄호는 대응하는 블록 수준에 맞춘다.
- Tab은 선택 줄을 들여쓰기하고 Shift+Tab은 선택 줄을 내어쓰기한다. 선택 없이 Tab을 누르면 커서 위치에 4칸 들여쓰기를 넣는다. 브라우저 기본 Undo/Redo, 붙여넣기, 선택/복사, IME 한글 입력을 망가뜨리지 않는다.
- 코드 초안이 문제 이동·새로고침 뒤 복원된다. 20,000자 제한과 저장/용량 오류 표시를 유지한다.
- 편집기의 키보드 조작을 화면에 간단히 안내하고, 들여쓰기 키가 키보드만 쓰는 사용자의 폼 이동을 막지 않도록 편집기를 벗어나 다음 버튼으로 이동할 방법을 제공한다.
- 320·390·768·1280px 화면과 라이트·다크에서 코드 편집 영역만 가로 스크롤되고 페이지 전체는 가로로 넘치지 않는다.

### 실행 결과와 정답 판정

- 실행 결과에는 상태(실행 중, 통과, 일부 실패, 실행 오류, 시간 초과), 표준 출력, 각 테스트의 입력 요약·기대값·실제값·결과를 구별해 표시한다. 오류/시간 초과 결과를 성공 문구와 섞지 않는다.
- 일반 JavaScript 코딩 문제는 공개된 여러 입력 사례로 요구 동작을 채점한다. 허용 가능한 답은 코드 문자열이 아니라 사례별 결과로 판정한다.
- 반환값 비교 규칙은 원시 값은 타입과 값이 같아야 하며, 배열은 순서가 같아야 하고, 객체는 속성의 집합과 각 값이 같으면 속성 선언 순서가 달라도 같다고 본다. 중첩 배열·객체도 같은 규칙으로 비교한다.
- 문자열 결과는 문제에서 별도로 지정하지 않는 한 정확히 비교한다. 줄바꿈이나 공백 무시는 문제의 요구 결과에 명시한 경우에만 정규화한다.
- `console.log` 표준 출력과 함수 반환값은 별개다. 실행 문제는 반환 동작을 기본 채점값으로 삼고, 출력 자체가 학습 목표일 때만 표준 출력을 명시적으로 기대 결과와 비교한다.
- 변수명, 코드 줄 배치, 괄호 주변 공백, 주석, 동등한 계산 순서는 결과를 바꾸지 않으면 정답을 막지 않는다. 모든 예제 테스트를 통과해야 정답 처리한다.
- 사례 기반 채점은 제공된 사례에서 관찰된 동작만 확인한다. 정적 사이트의 브라우저 번들에 포함된 사례는 비밀 테스트가 아니며 모든 가능한 입력에 대한 증명이나 부정행위 방지로 소개하지 않는다.
- 문제 초안은 기존 초안 복원, 다시 시도, 문제 이동 뒤 복원을 유지한다.

## 5. 권장 구현 순서와 대상 파일

### 단계 1 — 편집 방식 선택 완료

- CodeMirror 6 공식 문서에서 모듈 구성·언어 지원·스타일 삽입 방식을 확인하고 MIT 라이선스와 모바일 브라우저 지원 근거를 기록했다.
- 공식 npm 레지스트리에서 잠금 파일 기준으로 개발 의존성을 설치했다. 알려진 취약점 감사 결과는 0건이며, 악성코드 부재를 보증한다고 과장하지 않는다.
- 편집기 코드는 로컬 정적 파일로 묶고 배포 산출물에 타사 라이선스 전문을 포함한다. 브라우저에서 CDN·원격 패키지 요청을 하지 않는다.

### 단계 2 — 공통 편집기

- `src/main.js`: `repair-code`/`coding` 입력 공통 영역에 언어에 맞는 편집기 메타데이터와 접근 가능한 키 안내를 연결한다.
- `src/styles.css`: 기존 `--editor-*` 색상 토큰을 바탕으로 문법 색, 줄 번호, 선택 줄, 포커스, 실행 버튼/상태, 좁은 화면 규칙을 적용한다.
- 모든 기술 이름은 전체 표기를 사용한다. Spring/Java/React 트랙 코드 편집은 입력과 편집 기능을 제공하되 실행 불가 상태를 숨기지 않는다.

### 단계 3 — 키 처리와 초안 보존

- 기존 입력 저장 경계를 유지하면서 Enter 자동 들여쓰기, Tab 들여쓰기, Shift+Tab 내어쓰기와 필요한 키보드 탐색 경로를 추가한다.
- 탭/공백을 섞은 시작 코드, 빈 줄, 여러 줄 선택, 줄 시작/끝의 커서와 한글 IME 중 조작을 회귀 조건으로 삼는다.
- 문제가 바뀔 때 초안이 올바른 문항에 귀속되는지, 한도 초과를 조용히 잘라 저장하지 않는지 확인한다.

### 단계 4 — 결과 표시와 실행 경계

- `src/main.js`: 기존 `answerFeedback`과 중복되지 않게 코딩 문제의 결과 탭/영역에 실행 요약, 출력, 오류, 테스트별 기대·실제 결과를 렌더링한다.
- `src/runner.js`, `public/runner-frame.html`: 요청/응답 형식, 오류 종류, 반환값과 표준 출력을 분리한다. 원래의 sandbox 속성, CSP, 네트워크 금지, 입력/출력 상한, Worker 종료와 제한 시간을 약화하지 않는다.
- `src/content.js` 및 검수된 `src/curriculum-*` 데이터: 한 문제당 여러 입력, 빈 값/경계값/일반값을 포함하고 채점 대상 함수 계약을 명시한다. 정답 키, 힌트, 해설, 테스트 기대값이 같은 요구 동작을 설명해야 한다.

### 단계 5 — 동등성 채점

- `public/runner-frame.html`의 현재 JSON 문자열 비교를 전용 비교 함수로 바꾸는 방안을 구현한다. 한정된 지원 타입을 먼저 정하고 순환 참조/함수/클래스 인스턴스처럼 JSON 문항 계약 밖의 값은 학습 문제에서 허용하지 않거나 명확한 오류로 처리한다.
- `src/grading.js`의 정규식 기반 수정 문제 채점과 실행 문제의 행동 비교를 혼합하지 않는다. 수정 문제의 가능한 정답 경로는 해당 문제에 작성한 복수 정답 패턴/검사로 의도적으로 표현한다.
- 실패한 사례를 복사 가능한 입력·기대값·실제값으로 보여주되 학습 피드백이 지나치게 길어지지 않도록 사례 수를 제한한다.

### 단계 6 — 타 언어 조사 및 전체 통과

- Python/Java 브라우저 런타임 후보와 React 로컬 빌드/실행 경계를 공식 문서·라이선스·정적 배포 규모로 조사한다. 외부 원격 서비스로 코드를 보내는 후보는 제외한다.
- 런타임을 현재 static output에 포함하는 방법, 새 의존성 유지보수, 캐시 무효화/업데이트 시점, 브라우저별 호환성, 격리 한계와 번들 크기를 정량화한다.

## 7. 위험과 범위 경계

- **색상 표시와 실제 입력 정렬 불일치:** 편집기 글꼴, 탭 폭, 행간, 스크롤 위치를 단일 토큰으로 동기화하고 IME/확대 브라우저 수동 검증에서 어긋나면 더 단순한 표시로 조정한다.
- **코드 표시 XSS:** 사용자 입력과 토큰 값을 HTML로 바로 연결하지 않고 반드시 escape한다. 붙여넣은 HTML/JS가 표시 때 실행되지 않는지 확인한다.
- **행동 테스트가 모든 답을 보장하지 않음:** 테스트 사례는 요구의 대표/경계 상황을 함께 포함하고, 결과 판정은 해당 입력 집합에 한정됨을 정확하게 표현한다.
- **Worker 자원 제한:** 시간 제한과 출력/입력 상한을 보존한다. 브라우저 내 Worker가 메모리·CPU 격리를 완벽하게 보장한다고 표현하지 않는다.
- **다른 언어의 런타임 크기와 운영:** WASM이나 프레임워크 런타임이 파일 크기·실행 시간·라이선스·브라우저 지원 기준을 넘으면 넣지 않는다. 기능을 축소해도 서버나 외부 API로 우회하지 않는다.
- **Spring Boot의 기대치:** Java 문법 편집기와 Spring Boot 서버 실행은 다르다. Spring 문제는 실제 실행 가능한 환경이 확인되지 않으면 개념/검토 문제로 표시한다.
- **테마와 편집기 접근성:** 색상 차이만으로 구문 의미를 전달하지 않고 키워드·문자열·주석의 명도/색조와 포커스/선택 표시를 함께 검증한다.

## 8. 진행 규칙과 다음 단계

현재 유료 서비스 결정은 필요하지 않다. CEX-6은 현재 정적 무료 경계에서 런타임을 추가하지 않는 조사 결과로 완료했다. 실행 불가 트랙을 실행 가능한 것처럼 표시하지 않는다. 미완료 검증은 실제 OS 한글 IME 조합 및 다른 브라우저 1종이다. 현재 연결된 브라우저 환경에는 Chrome과 Codex 인앱 브라우저만 있어 다른 엔진 검증은 수행할 수 없었다. 타 언어 실행 런타임은 크기·라이선스·보안 검토와 별도 결정 기록 없이 추가하지 않는다.
