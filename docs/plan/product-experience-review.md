# 제품 전체 경험 점검 및 후속 개선 계획

- 작성일: 2026-10-16 (Asia/Seoul)
- 상태: 0–3, 5–8단계 완료. 2026-10-30 격리 브라우저에서 학습·저장·정답 기록·백업 왕복·문제 이동 뒤 스크롤 초기화·390px 화면·공식 문서 접힘을 확인했다. 전체 자동 검사 508/508 및 릴리스 검사를 통과했다. 긴 제목의 한국어 어절 중간 줄바꿈, 짧은 코딩 입력 예제, 문제 본문에 적힌 줄바꿈의 표시를 고쳐 내부 브라우저에서 확인했다. 4단계는 실제 Windows 한글 IME 조합이 미검증이다. 초보 관찰은 가능한 경우 수행하며 참여자가 없으면 전문가 점검으로 표시한다. 사용자는 200% 확대 검사를 우선순위에서 제외했다.
- 범위: 학습 흐름, 화면/UI·UX, 가독성·접근성, 문항 정확도와 문제 유형, 프로그래밍 언어 및 UI 언어 확장, 브라우저 저장·백업, 로그인·기기 동기화, 공개 피드백 경로
- 기본 경계: 기존 무료·한국어 우선·로컬 저장 원칙을 유지한다. 새 로그인, 계정, 클라우드 저장, 추적 분석, 유료/외부 서비스를 계획 단계에서 도입하지 않는다.
- 근거: [README 현황](../../README.md#L7), [제품·구조 규칙](../../docs/rules/product.md#L9), [브라우저 저장 규칙](../../docs/rules/architecture.md#L15), [개인정보 규칙](../../docs/rules/privacy-security.md#L6), [디자인 규칙](../../docs/rules/design.md#L8), [콘텐츠 규칙](../../docs/rules/content.md#L5), [진척 기록](../../docs/plan/progress.md#L7), [공개 카탈로그 현황](../../docs/plan/content-roadmap.md#L9)

## 1. 목표

초보 학습자가 가입 없이 첫 학습을 시작하고, 문제를 이해해 풀고, 오답에서 다음 시도를 찾고, 같은 브라우저에서 진도를 이어갈 수 있는지 확인한다. 오류와 불편은 재현 근거와 영향도에 따라 정리하고, 높은 우선순위부터 작게 수정한다.

계획 완료는 새 언어·문항·로그인을 반드시 추가했다는 뜻이 아니다. 증거가 없는 요구는 미확정으로 남기고, 새 콘텐츠와 외부 서비스는 해당 결정 관문을 통과한 경우에만 범위를 정한다.

## 2. 기준선과 이미 알려진 경계

- 공개 사이트는 2026-10-16 확인 기준 다섯 트랙·23개 단원이다. G10·G11을 포함한 이후 학습 자료와 저장 문구 변경은 로컬 트리에 있으며 공개 사이트와 혼동하지 않는다. (`README.md:7`, `docs/plan/content-roadmap.md:9`)
- CQ-7 콘텐츠 감사와 G10/G11 편집 검수는 완료 기록이 있다. 기존 콘텐츠 전체 감사를 그대로 반복하지 않고, 실제 학습 경로에서 발견한 불일치·오류와 버전 변경 항목을 집중 확인한다. (`docs/plan/progress.md:17-27`, `docs/plan/content-roadmap.md:5`)
- 제품 원칙은 앱 로그인 없이 핵심 학습을 제공하는 것이다. 진도는 현재 브라우저에 저장하고 JSON 백업/복원을 제공한다. 다중 기기 동기화는 H-03으로 남아 있지만 현재 차단 결정은 아니다. (`docs/rules/product.md:9,25`, `docs/rules/architecture.md:15-20`, `docs/plan/decisions-and-help.md:45`)
- 코드 편집기 한글 IME 및 추가 브라우저 확인이 별도 보완 항목이다. (`docs/plan/progress.md:13,16`)
- 공개 피드백은 GitHub Issues를 사용하며 GitHub 로그인 안내가 있다. 이 마찰을 앱 로그인의 근거로 간주하지 말고 제보 경로 자체를 별도 검토한다. (`docs/plan/release-checklist.md:7,34-42`)

## 실행 기록 (2026-10-16)

### 0단계 — 기준선 고정 완료

- 기준 커밋은 `086f4a5`다. 확인 시점에 이미 소스·문서·검사 파일을 포함한 작업 트리가 수정/미추적 상태였고, 기존 변경은 보존했다.
- 비교 환경은 공개 사이트 `https://code-one-step.pages.dev/`와 로컬 미리보기 `http://127.0.0.1:4173/`다. 로컬 미리보기는 현재 작업 트리의 빌드 결과를 제공한다.
- 공개본은 5개 트랙·23개 단원으로 보이고, 첫 화면 저장 표시는 “저장 준비 중”이다. E-257에서 기록한 공개/로컬 저장 상태 차이가 여전히 보인다.
- 로컬 새 프로필에서는 11개 학습 트랙과 별도 공통 실무 기초 경로, 324주 기준 0주 완료가 확인됐다. 저장 표시는 “이 기기에 저장”이다. 새 프로필은 `fresh.localhost:4173`의 별도 브라우저 출처로 분리했다.

### 1단계 — 학습자 여정 점검 완료

- 격리 프로필에서 홈 → 배울 주제 → JavaScript → 첫 학습 구간 → 변수와 상수 → 첫 객관식 문제로 이동했다. 과정은 학습 목표, 예제, 하루 3문제·주 15문제 안내와 다음 주차 링크를 제공한다.
- **P1, E-258:** 트랙 목록 제목은 “11개 트랙”이라고 하지만 분류 목록에는 8개 카드만 나타났다. FastAPI, Kotlin · Android, C# · .NET은 홈/사이드바에서는 보이지만 트랙 목록에서 빠진다. 카테고리 문자열을 정확히 세 값과 비교하는 목록 분류가 원인이다. 상세 재현과 수정 조건은 `decisions-and-help.md`의 E-258에 기록했다.
- 문제에는 객관식 선택, 답 확인, 접을 수 있는 힌트와 해설이 있다. 격리 프로필에 오답 하나를 제출했을 때 “다시 풀어 보세요”라는 안내와 개념 설명이 나타났고, “답을 저장했어요” 알림도 확인했다. 홈의 이어하기는 같은 문제를 가리키며 최근 풀이에도 “다시 풀기”로 나타났다. 오답이라 완료 진도는 0/15로 유지된다.
- 앱은 로그인 없이 학습하고 이 기기에 저장한다고 안내한다. 공개 오류 제보 링크는 GitHub 로그인이 필요하다고 표시한다. 실제 사용자 관찰 없이 수행한 휴리스틱 점검이므로 초보자의 성공률이나 혼동 빈도를 추정하지 않는다.
- **범위 한계:** 실제 초보 학습자 관찰은 하지 않았으므로 사용자 성공률·혼동 빈도는 추정하지 않았다. 200% 확대 검사는 사용자 요청에 따라 이번 점검에서 제외한다.

### 2단계 — 저장·백업 신뢰성 점검 완료

- 별도 출처 `audit2.localhost:4173`에서 합성 정답 기록 1개를 저장하고 문제 화면을 새로고침했다. 새로고침 뒤 정답 표시와 1/15 진도, 기록 화면의 최근 풀이와 100% 정답률이 유지됐다. 저장 표시는 “이 기기에 저장”이다.
- 기록 화면의 “기록 파일 내보내기”를 눌러 JSON 다운로드 완료 알림을 확인했다. 실제 학습 기록이나 사용자 계정 정보는 사용하지 않았다.
- `npm test -- tests/progress.test.js tests/progress-storage.test.js`가 30/30 통과했다. 테스트에는 백업 왕복, 손상/미지원 버전/1MB 초과 파일 거부, 기존 유효 기록 보존, IndexedDB 장애 시 브라우저 저장소 대체, 양쪽 저장소 실패 및 복구가 포함된다.

- **검증:** `node --test --test-reporter=spec tests/progress-storage.test.js tests/design.test.js` 34/34 통과, `npm run build` 성공. 저장 실패 전후 UI와 재시도·새로고침 결과를 브라우저에서 확인했다. 따라서 2단계의 저장 실패 UI 조건을 완료한다.

### 4단계 — UI/UX·가독성·접근성 부분 검증

- 홈, 트랙 목록, 학습, 객관식 문제, 코딩 문제, 기록 화면을 격리 브라우저에서 확인했다. 320/390/768/1280px 모두 문서 가로 넘침이 없었다. 320px에서 HTML의 최소 너비가 스크롤바 가용 폭과 겹치는 문제를 발견해 `html`·`body`의 최소 너비를 0으로 고쳤다. 이후 320px에서 여섯 화면 모두 문서 `clientWidth`와 `scrollWidth`가 305px로 일치했다. 나머지 폭은 각각 375/753/1265px로 일치했다.
- 모바일 5개 메뉴의 표시 글자를 14px로 맞추고 각 메뉴에 전체 접근성 이름이 제공되는 것을 확인했다. 일반 UI의 작은 글자·안내·상태 문구도 14px 기준으로 조정했으며 장식용 번호만 예외로 남겼다. 관련 디자인 회귀와 라이트/다크 대비 자동 검사를 추가했다.
- 밝은/어두운 테마를 화면에서 확인했다. 키보드만으로 문항 선택 후 답 확인을 실행하고 정답 피드백과 저장 상태를 확인했다. 브라우저 오류/경고 로그는 없었다.
- **한글 입력 확인:** 격리된 코딩 편집기에 `// 한글 입력 확인: 안녕하세요`를 넣고 읽어 들인 값이 정확한 것을 확인했다. 이는 한글 문자열 수용 확인이며 OS IME 조합 검증은 아니다. 자동화 키 입력은 `dkssud`를 한글로 조합하지 않고 영문 자판 문자열로 전달했다. OS IME 상태를 제어하는 별도 브라우저 창은 이 세션에서 조작할 수 없어 실제 조합 입력은 미검증으로 둔다(CEX-3).
- 2026-10-28 재시도: 격리된 로컬 브라우저 탭에서 학습 화면은 열렸지만 OS IME 입력을 보낼 수 있는 네이티브 Edge 창은 현재 URL 판별이 되지 않아 Computer Use가 화면 확인을 거부했다. 정확한 로컬 주소와 임시 프로필로 별도 창을 여는 시도는 실행 환경 정책에 막혔다. 입력을 전송하거나 붙여넣지 않았으며 실제 한글 조합은 계속 미검증이다.
- 추가 재시도: 현재 실행 중인 Edge는 브라우저 목록에는 나타나지만 Computer Use가 조작 가능한 창 목록에는 반환되지 않았다. 네이티브 입력 대상이 없어 IME 조합을 시도하지 않았고, 미검증 상태를 유지한다.

### 6단계 — 언어 및 로그인/동기화 결정 완료

- D-31: 현재 로컬 카탈로그에 11개 트랙(11개 중 다양한 프로그래밍 언어·프레임워크 과정)이 있고 추가 과정 수요를 입증하는 사용자 요청/관찰 근거는 없다. 새 과정을 더하기보다 기존 로컬 과정과 아직 공개되지 않은 5개 트랙 차이를 먼저 관리한다. 새 과정 후보는 별도 수요와 검수 근거가 생길 때 결정한다.
- D-32: UI 번역은 프로그래밍 언어 과정 추가와 분리한다. 현재 요구는 한국어 우선이므로 다른 UI 언어는 수요가 확인될 때까지 보류한다. 확인된 다국어 수요는 없다.
- D-33: 로그인·클라우드 동기화는 현재 추가하지 않는다. 학습은 가입 없이 제공하고 현재 브라우저에 저장하며, 기기 이동은 검증된 JSON 내보내기/가져오기를 사용할 수 있다. 다중 기기 상시 동기화 요청은 확인되지 않아 H-03은 비차단·미결정으로 유지한다. 동기화 요구가 생기면 개인정보, 계정 삭제/내보내기, 충돌, 비용과 운영 책임을 먼저 재검토한다.

## 4. 완료 기준

1. 공개본과 작업 중 로컬본의 차이가 추적 가능하게 기록된다.
2. 핵심 여정에서 발견한 모든 문제에 재현 근거, 심각도, 완료 조건이 있다.
3. 확인한 문제의 답·해설·예제·실행 표시가 실제 학습 목표 및 공식 버전 기준과 일치한다.
4. 저장/백업의 정상·실패·잘못된 입력 흐름에서 기록 손실 여부와 사용자 안내를 확인한다.
5. 모바일·키보드·테마·가독성의 검토 결과를 화면 폭 및 재현 단계와 함께 기록한다.
6. 추가 프로그래밍 언어, UI 번역, 로그인/동기화는 각각 근거와 상태(진행/보류/결정 필요)가 문서화된다.
7. 수정 후 계획에서 정한 검증을 실행하고, 미실행 항목은 완료로 세지 않는다.

## 5. 위험과 대응

- 공개본과 로컬본이 달라 잘못된 화면을 점검할 수 있다 → 0단계에서 URL/커밋/카탈로그를 고정하고 모든 발견에 환경을 적는다.
- 대규모 문항을 전부 다시 검수해 피드백 대응이 늦어질 수 있다 → 이미 승인된 CQ 범위는 재사용하고 실제 과업, 신고, 버전 변경에 따라 위험 기반으로 표본을 고른다.
- 저장 테스트가 기존 기록을 덮어쓸 수 있다 → 격리 프로필과 인공 데이터만 사용한다.
- 초보자 사용자 증거가 없을 수 있다 → 휴리스틱 결과와 실제 관찰 결과를 구분하고, 관찰하지 않은 효과를 주장하지 않는다.
- 로그인을 먼저 추가하면 운영/개인정보 부담이 생긴다 → H-03 결정 관문 전에는 계정이나 원격 데이터 경계를 만들지 않는다.
- 문제 수나 트랙 수 자체가 성과처럼 취급될 수 있다 → 추가 콘텐츠는 확인된 목표 공백을 해결하는지로 승인한다.
